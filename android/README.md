# KardioMonitor — Android-приложение

Прототип приложения для наблюдения за пациентами, проходящими реабилитацию после
инфаркта миокарда. Читает данные с фитнес-браслета **Xiaomi Mi Smart Band 6 (XMSH15HM)**
напрямую по Bluetooth LE, без облака Xiaomi.

> Данные бытового браслета не являются медицинскими измерениями и подходят для
> наблюдения за динамикой, но не для диагностики.

## Band 9: ограниченная production-интеграция

Обычная **M2345B1 / firmware 2.3.98** подключается отдельным RFCOMM/SPP-драйвером,
не кодом probe и не через Huami. Выбор протокола явный, новая выдача использует
[QR v3](docs/qr-contract.md); старые QR и сохранённые привязки Band 6 читаются по-прежнему.
Ключи остаются зашифрованными Android Keystore. Доступны только авторизация с проверкой
watch HMAC, заряд и GET настроек пульса; неизвестные поля не превращаются в нули,
interval=0 — Smart, не «Выкл».

**Полная поддержка Band 9 не готова:** history/time/values, today steps, безопасный live stop,
SET с восстановлением и клинический/фоновый E2E не подтверждены. Эти операции явно
заблокированы, а не заменены sample-данными. Команда history ACK 8/5 отсутствует.
Статусы аппаратной проверки — в [чек-листе](../docs/band9-validation-checklist.md),
безопасный отдельный тестовый APK — в [testing.md](docs/testing.md).
Не устанавливать приложения поверх личного телефона ради end-to-end проверки.

## Возможности Band 6

- Привязка браслета по QR-коду клиники или вводом MAC-адреса и ключа.
- Авторизация по протоколу Huami 2021 (прошивка 1.0.6.10+).
- Заряд браслета, шаги за сегодня, пульс в реальном времени (для тренировок).
- Поминутная история пульса и шагов в локальной базе, синхронизация по кнопке и
  в фоне каждые 30 минут.
- Настройка частоты фонового измерения пульса (1, 5, 10, 30 мин, выкл).
- Итоги дня: шаги, пульс ср/мин/макс, покрытие пульсом, график пульса за сутки,
  шаги по часам, навигация по дням.
- План реабилитации с сервера: день и этап программы, целевая зона, нормы тренировки и
  шагов, локально рассчитанный результат выбранного дня и прогресс по завершённым дням.
- Оповещения клиники: получение после синхронизации, локальный список и отдельный канал
  системных уведомлений без повторного показа обновлённого оповещения. Включая превышение
  тренировочных минут: день, фактические минуты и порог на момент первого обнаружения сервером;
  телефон не пересчитывает этот исторический снимок по текущему плану.
- Непрерывный пульс по запросу врача: телефон забирает запрос после любой попытки синхронизации,
  измеряет заданное время в видимом `connectedDevice` foreground-режиме и сохраняет отчёты до
  отправки. Пациент может остановить измерение из постоянного уведомления.
- Локальные напоминания «Пора пройтись», «Норма дня» и «Наденьте браслет»: условия по
  истории, дневное окно, дни недели, интервалы, ограничение частоты и отложенный повтор.
- Отправка данных на сервер клиники (`../backend`, для демо — через ngrok): привязка по
  одноразовому коду QR v2 или демонстрационная регистрация по имени, новые минуты после
  каждой синхронизации, «пульс сейчас».
- Ключ браслета и токен сервера зашифрованы ключом Android Keystore; открытые значения
  прежней версии переносятся автоматически.

## Требования

- JDK 21, Android SDK (platform 36), Gradle wrapper в репозитории (9.4).
- Телефон с Android 8.0+ и BLE. Эмулятор для работы с браслетом не подходит.
- Ключ авторизации браслета — см. корневой [README](../README.md), раздел
  «Получить ключ авторизации».

## Сборка и запуск

```bash
./gradlew assembleDebug        # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew installDebug         # установить на телефон, подключённый по adb
./gradlew testDebugUnitTest    # модульные тесты
./gradlew lintDebug            # статический анализ
```

QR-код для пациента (из корня репозитория):

```bash
python tools/make_qr.py --mac E7:19:F3:6C:04:9E --out band.svg   # ключ — из MIBAND_AUTH_KEY
```

Перед подключением на телефоне нужно закрыть Mi Fitness или отключить ей разрешение
«Устройства поблизости»: браслет держит одно соединение. Для стабильной фоновой
синхронизации: «Настройки → Приложения → KardioMonitor → Батарея → Без ограничений».

Для запросов пульса врача один раз откройте на главном экране карточку «Запрос пульса от
клиники» и подтвердите системную ассоциацию уже привязанного браслета. Это обычная Companion
Device Manager association по MAC, она не перепривязывает браслет и нужна Android для
разрешённого запуска измерения из фона. Уведомления приложения должны быть разрешены: без
видимого уведомления и действия «Остановить» запрос не выполняется.

## Структура

```
android/
  CLAUDE.md          # инструкции для ИИ-агента (Claude Code)
  .claude/           # настройки агента: hooks, skills проекта, подагент-ревьюер
  docs/              # архитектура, домен, правила кода, тесты, протокол, ADR
  app/src/main/java/ru/kardiomonitor/
    app/             # композиционный корень: Application, MainActivity, AppContainer, главный экран
    features/band/   # контекст «Браслет»: привязка, подключение (общий сеанс связи), частота пульса
    features/monitoring/  # контекст «Мониторинг»: синхронизация истории (кнопка + фон),
                     # пульс сейчас, шаги сегодня, итоги дня
    features/clinic/ # контекст «Обмен с клиникой»: регистрация на сервере, отправка минут и пульса
    features/rehab/  # контекст «Реабилитация»: кэш плана, синхронизация, локальный прогресс и UI
    features/alerts/ # контекст «Оповещения»: локальный журнал, синхронизация, уведомления и список
    features/reminders/ # контекст «Напоминания»: настройки, правила, фоновые проверки и уведомления
    platform/        # GATT-клиент, протокол Mi Band 6 (ACL HuamiBand), SQLite, HTTP, тема и графики
  app/src/test/      # тесты домена, сценариев (на фейках), протокола и архитектурные (architecture/)
```

Код организован по контекстам и вертикальным слайсам, см. [docs/architecture.md](docs/architecture.md).

## Ограничения прототипа

- Подтверждение выгрузки браслету не отправляется — данные остаются и для Mi Fitness
  ([ADR-0002](docs/adr/0002-keep-history-on-band.md)).
- Данные о сне не расшифрованы.
- Сервер возвращает телефону только текущую версию плана. Исторические версии доступны
  локально лишь с момента, когда телефон их получил; полное восстановление истории после
  переустановки потребует отдельного API.
- Тексты оповещений пациенту пока черновые и требуют утверждения врачом до выпуска (В-19).
- Нет подписанной release-сборки и иконки приложения.
- Утилита персонала для выпуска QR v2 пока существует только как спецификация.
