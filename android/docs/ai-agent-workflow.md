# Работа с ИИ-агентом

Как ставить задачи агенту (Claude Code и аналогам) и как агенту их выполнять в этом
проекте. Основано на
[рекомендациях Anthropic по Claude Code](https://code.claude.com/docs/en/best-practices)
и [документации по CLAUDE.md](https://code.claude.com/docs/en/memory).

## Главные принципы

1. **Контекст — главный ресурс.** Чем больше агент прочитал лишнего, тем хуже он
   следует правилам. Поэтому код организован слайсами: для задачи нужна одна папка.
2. **У задачи должна быть проверка.** Тест, сборка, строка в журнале устройства.
   Без проверки агент останавливается, когда работа «выглядит готовой».
3. **Сначала разобраться, потом план, потом код.** Особенно если задача затрагивает
   несколько файлов или протокол браслета.
4. **Правила, которые можно проверить автоматически, должны проверяться автоматически**
   (тесты, lint, архитектурные тесты, hooks), а не только описываться текстом.

## Цикл задачи

```
Разобраться → План → Реализация → Проверка → Документы → Ревью → Коммит
```

| Шаг | Что делает агент | Результат |
|---|---|---|
| Разобраться | Читает `CLAUDE.md`, нужный раздел `docs/`, код **одного** слайса. Широкий поиск — через подагента | Понимание, где менять |
| План | Для задач на несколько файлов — план в режиме планирования: какие слайсы, какие доменные типы, какие тесты | Согласованный план |
| Реализация | Пишет код по [coding-rules.md](coding-rules.md) внутри слайса; доменные правила — в домене | Изменения |
| Проверка | `./gradlew testDebugUnitTest lintDebug assembleDebug`; для BLE — журнал `KardioBLE` на телефоне | Вывод команд как доказательство |
| Документы | Обновляет глоссарий, карту слайсов, протокол, ADR — если они изменились | Актуальные `docs/` |
| Ревью | Свежий взгляд: подагент `architecture-reviewer` (границы, домен, правила) и `/code-review` (ошибки) по `git diff` | Список проблем по существу |
| Коммит | Только по просьбе человека. Репозиторий общий на `KardioMonitor/`: в коммит — только файлы задачи (`git add android/…`), без CSV, QR и ключей | — |

Пропускать план можно, если изменение описывается одним предложением
(переименование, текст на экране, константа).

## Как ставить задачу агенту

Шаблон:

```
Контекст: <контекст и слайс, напр. monitoring/dailysummary>
Задача: <что должно появиться/измениться для пользователя>
Правила предметной области: <например, «пульс покоя — минимум 5-минутного среднего за ночь»>
Готово, когда:
  - <проверяемый критерий 1, напр. тест `пульс покоя не считается по минутам без браслета`>
  - <критерий 2, напр. в журнале KardioBLE строка ...>
Вне задачи: <что не трогать>
```

Плохо: «сделай статистику лучше».
Хорошо: «В слайсе `monitoring/dailysummary` добавь пульс покоя: минимум скользящего
среднего за 5 минут, только по минутам, где браслет надет. Новые термины — в глоссарий.
Тесты: дневные данные без пульса → пульс покоя не показывается; минуты `NotWorn` не
учитываются. Проверка: `./gradlew testDebugUnitTest`».

Для больших функций попросите агента сначала **проинтервьюировать вас** и записать
спецификацию в `docs/specs/<название>.md`, а реализацию начинать в новой сессии.

## Чего агенту не делать без явного согласования

- Менять протокол браслета без тестов с эталонными байтами ([testing.md](testing.md)).
- Отправлять браслету `03` (подтверждение выгрузки) — удалит историю ([ADR-0002](adr/0002-keep-history-on-band.md)).
- Открывать второе соединение с браслетом в обход `BandConnection`.
- Логировать или коммитить ключ авторизации, содержимое QR, `local.properties`.
- Добавлять библиотеки (нужен ADR) и менять версии AGP/Kotlin/Gradle.
- Удалять или переписывать данные на телефоне пациента (`pm clear`, удаление базы).
- Делать широкий рефакторинг «заодно».

## Управление контекстом (Claude Code)

- `/clear` между несвязанными задачами.
- Исследование кода и поиск в интернете — через подагентов: они читают много, а в
  основной контекст возвращают выводы.
- После двух неудачных исправлений одного и того же — `/clear` и новая, более точная
  постановка с учётом выясненного.
- `CLAUDE.md` короткий (< 200 строк); подробности — в `docs/` и читаются по ссылке,
  когда нужны. Длинный `CLAUDE.md` агент выполняет хуже.
- **Запускать Claude Code из `android/`**, а не из корня репозитория. Git общий на
  `KardioMonitor/`, но настройки агента у каждого проекта свои: `android/.claude/`
  (hooks, skills, подагенты) подхватываются, только когда `android/` — рабочий каталог.

## Skills и подагенты проекта

Лежат в `.claude/` и подхватываются автоматически. Повторяющиеся сценарии описаны
один раз — агент не восстанавливает порядок шагов из нескольких документов.

| Что | Когда |
|---|---|
| `/new-slice <контекст>/<слайс>` | Новый пользовательский сценарий: структура слайса, домен, фейки, тесты |
| `/protocol-change` | Любая правка в шифровании, пакетах, форматах браслета |
| `/migration-step <N>` | Шаг плана миграции из [architecture.md](architecture.md) (миграция завершена; skill — образец для будущих переносов) |
| подагент `architecture-reviewer` | Ревью диффа на соответствие architecture.md, domain-model.md, coding-rules.md |

## Внешние skills

Инструкции, которые агент подгружает по необходимости. Сторонний skill — это текст,
который агент будет выполнять: **перед установкой прочитать `SKILL.md`**, после
установки — закоммитить его в `.claude/skills/`, чтобы версия была зафиксирована.
Правила проекта ([architecture.md](architecture.md), [coding-rules.md](coding-rules.md))
**главнее** сторонних skills: если skill советует иначе (Hilt, Room, класс UseCase на
каждое действие, Mockito), следуйте документам проекта.

| Skill | Источник | Когда подключать |
|---|---|---|
| `jetpack-compose` | [android/skills](https://github.com/android/skills) (Google) | Любая работа с экранами и секциями слайсов |
| `testing-setup` | android/skills | Robolectric, UI-тесты Compose, `androidTest` |
| `security` | android/skills | Хранение ключа браслета (Keystore), разрешения Bluetooth и камеры |
| `navigation` | android/skills | Когда появится больше одного экрана |
| `edge-to-edge` | android/skills | Отступы системных панелей |
| `agp-9-upgrade`, `r8-analyzer` | android/skills | Обновление AGP; release-сборка с R8 |
| `vertical-slice-architecture` | [mryll/skills](https://github.com/mryll/skills) | Фон для [architecture.md](architecture.md) |
| `test-namer` | mryll/skills | Имена тестов по В. Хорикову |
| `domain-driven-design` | [booklib-ai/booklib](https://github.com/booklib-ai/booklib) | Моделирование новых контекстов (реабилитация, обмен с клиникой) |
| `effective-kotlin` | booklib-ai/booklib | Идиомы Kotlin |

Установка (из `android/`):

```bash
# Официальные Android skills — Android CLI: https://developer.android.com/tools/agents/android-cli
# --agent=claude обязателен: без папок агентов skills по умолчанию уходят в ~/.gemini
android skills add jetpack-compose --agent=claude --project=.
android skills add testing-setup --agent=claude --project=.
android skills add security --agent=claude --project=.

# Сторонние skills (CLI skills.sh) — сначала прочитать SKILL.md в репозитории
npx skills add mryll/skills --skill vertical-slice-architecture
npx skills add mryll/skills --skill test-namer
npx skills add booklib-ai/booklib --skill domain-driven-design
```

Обновление — `android skills update --all`, затем просмотр диффа `.claude/skills/`.

## Hooks

Hooks выполняются всегда, в отличие от текста в `CLAUDE.md`. Настроены в
[`.claude/settings.json`](../.claude/settings.json), скрипты — в `.claude/hooks/`.

| Hook | Что делает |
|---|---|
| `Stop` → `unit-tests-on-stop.sh` | Если `.kt`/`.kts`/`.toml`/`.xml` менялись после последнего зелёного прогона — запускает `testDebugUnitTest` (с архитектурными тестами) и не даёт завершить ход, пока тесты падают |
| `PreToolUse(Bash)` → `guard-patient-device.sh` | Через adb блокирует очистку данных приложения, его удаление, удаление базы и настроек; блокирует вывод переменной с ключом браслета |

Охранник проверяет текст команды, поэтому срабатывает и на heredoc, где такая
команда только упомянута. Документы правьте инструментом Edit, а не через shell.

Hook не заменяет проверку: `lintDebug` и `assembleDebug` перед завершением задачи
запускаются вручную. Личные настройки — в `.claude/settings.local.json` (не в git).
