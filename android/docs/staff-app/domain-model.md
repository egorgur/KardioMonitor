# Утилита персонала — модель предметной области

Единый язык утилиты. **Имена в коде берутся из этой таблицы**; нет термина — сначала сюда.
Общие правила записи — [../domain-model.md](../domain-model.md). Термины, совпадающие с
приложением пациента (`BandAddress`, `AuthKey`, `BatteryLevel`), означают то же самое и
подчиняются тем же правилам; объявлены в утилите заново (ADR-0007: приложения не зависят
друг от друга).

Предметная область: подготовка и выдача Mi Smart Band 6; Band 9 имеет ограниченную
read-only foundation M2345B1 / 2.3.98 без готовности клинического мониторинга.

## Глоссарий

### Контекст «Браслеты клиники» (`features.inventory`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Браслет клиники | `ClinicBand` | Aggregate root | Браслет, привязанный к аккаунту клиники: адрес, ключ, метка (может отсутствовать), модель, прошивка по данным облака, откуда получен ключ, когда. Идентичность — `BandAddress` |
| Адрес браслета | `BandAddress` | Value Object | MAC `AA:BB:CC:DD:EE:FF`, верхний регистр — как в приложении пациента |
| Ключ авторизации | `AuthKey` | Value Object | 16 байт (32 hex, нижний регистр). **Секрет**: `toString()` скрывает, не логируется, хранится только шифротекстом (ADR-0010) |
| Метка браслета | `BandLabel` | Value Object | Надпись на наклейке браслета («Б-07»): 1–20 знаков, без пробелов по краям; уникальна среди браслетов клиники (сравнение без учёта регистра) |
| Протокол браслета | `BandProtocol` | `enum` | `MiBand6Ble` (`mi-band6-ble`), `XiaomiBand9Spp` (`xiaomi-band9-spp`), `Unknown`. Явный выбор UI; default старых конструкторов/миграций — Band 6. Неизвестное сохранённое значение → `Unknown`, подключение и QR запрещены |
| Модель браслета | `BandModel` | Value Object | Соответствие проверяет `shared.BandProtocol.supports(model.value)`; Band 9 допускает обычный Xiaomi Smart Band 9 / M2345B1, точную модель/firmware подтверждает wire guard, не Bluetooth-имя |
| Источник ключа | `KeyOrigin` | `enum` | `MiFitnessCloud`, `ZeppLifeCloud`, `Manual` |
| Хранилище браслетов | `BandInventory` | Repository (интерфейс) | `bands: Flow<List<ClinicBand>>`, `byAddress`, `save`, `remove`. Ключ возвращается только через `api.IssuableBands` и `bandcheck` — не в список |
| Источник ключей | `BandKeySource` | Порт (интерфейс в `domain`) | Облако на языке утилиты: `cloudBands(): CloudBandsResult` — список (адрес, ключ, модель, прошивка) или отказ (`NotSignedIn`, `Unavailable`). Реализует ACL `platform.xiaomi`, сеанс входа — внутри ACL |
| Получение из облака | `SyncCloudBands` | Сценарий (слайс `cloudsync`) | Новые браслеты добавляются, у известных обновляется ключ (если перепривязаны) и прошивка; метки сохраняются. Браслет, которого больше нет в облаке, **не удаляется** — помечается «нет в аккаунте» |

### Контекст «Проверка браслета» (`features.bandcheck`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Проверка браслета | `CheckBand` | Сценарий | Явный протокол → свой inspector без fallback. Band 6 сохраняет запись интервала 1 мин. Band 9 только HMAC/model guard/чтение заряда и GET HR settings, без SET/live/history/steps |
| Итог проверки | `BandCheck` | Value Object | Адрес, протокол, момент, `CheckOutcome`, прошивка, nullable заряд, nullable интервал и disabled. Band 9 0 = Smart, null ≠ 0/false; результат всегда Warning об ограничениях |
| Исход проверки | `CheckOutcome` | `sealed interface` | `Ready` — готов к выдаче; `Warning(reasons)` — можно выдать, но: прошивка не проверена, заряд низкий; `Failed(problem)` — нельзя: не найден, ключ не подошёл, сбой связи, нет Bluetooth/разрешения |
| Проверенная прошивка | `TestedFirmware` | Правило (`object`) | Список версий, на которых протокол проверен (сейчас `V1.0.6.10`, [ble-protocol.md](../ble-protocol.md)). Другая версия — предупреждение |
| Порог заряда | `BatteryLevel.isEnoughForIssue` | правило `BatteryLevel` | ≥ 30 % — выдавать; меньше — предупреждение «зарядить» |
| Частота пульса при выдаче | `IssueHeartRateInterval` | Правило (`object`) | 1 минута (поминутная история для реабилитации). Приложение пациента перезапишет её, если пациент выберет другую |
| Проверяющий | `BandInspector` | Порт (интерфейс в `domain`) | Браслет на языке проверки: `inspect(address, key, interval): InspectionResult`. Реализует ACL `platform.band` |
| Журнал проверок | `BandCheckLog` | Repository | Последняя проверка браслета; `latestOf(address)` |
| Свежесть проверки | `BandCheck.isFreshAt(now)` | правило | Проверка моложе 24 ч и `Ready`/`Warning` — выдавать без повторной проверки |

### Контекст «Выдача» (`features.issuance`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Код привязки | `PairingCode` | Value Object | Только v3: `kardio3;<protocol>;<MAC12 uppercase>;<key Base64url unpadded 22>`, оба протокола. Unknown отвергается. **Секрет**: `toString()` скрывает. Старый regex MAC+hex32 намеренно не распознаёт v3; legacy читает пациент |
| Выдача | `Issuance` | Entity | Адрес, метка и протокол на момент выдачи, когда выдан/возвращён (null — на руках). Сохранены в SQLite; протокол открытой выдачи обязан совпадать с QR. **Без данных пациента** |
| Журнал выдачи | `IssuanceLog` | Repository | `open(address)`, `current(address)`, `history: Flow`, `returned(address, at)` |
| Браслет на руках | `Issuance.isOpen` | правило | Не возвращён. Повторная выдача браслета на руках — только после «Возвращён» (защита от путаницы меток) |
| Возврат | `IssuanceLog.returned` | правило | Закрывает выдачу; ключ браслета не меняется — следующему пациенту выдаётся тот же `PairingCode` ([ADR-0011](../adr/0011-band-reissue-keeps-key.md)) |
| Показ QR | `qrdisplay` | Слайс | Полный экран, `FLAG_SECURE`, яркость максимум, закрытие через 2 мин; открывает `Issuance`, если браслет не на руках |

### Контекст «Аккаунт клиники» (`features.account`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Аккаунт клиники | `ClinicAccount` | Value Object | Логин аккаунта Xiaomi (email/телефон) — для отображения «вошли как …». Пароль не хранится |
| Состояние входа | `SignInState` | `sealed interface` | `SignedOut` или `SignedIn(account)`. Публикуется `AccountGateway.state: StateFlow` и `account.api` |
| Шлюз аккаунта | `AccountGateway` | Порт | `signIn(login, password): SignInResult`, `signOut()`, `state`. Реализует ACL `platform.xiaomi` |
| Результат входа | `SignInResult` | `sealed interface` | `SignedIn(account)`, `WrongCredentials`, `ConfirmationRequired` (капча, вход с нового устройства — подтвердить в Mi Fitness и повторить), `Unavailable` (нет сети, сбой облака) |

Сеанс облака (`ssecurity`, `serviceToken`, токен Huami) — **не доменное понятие**: он живёт
только внутри ACL `platform.xiaomi`, в памяти процесса, и не выходит из него. Закрытие
приложения или «Выйти» — сеанс забыт. Домен знает лишь, вошли ли и под каким логином.

## Агрегаты и инварианты

| Агрегат | Корень | Инварианты |
|---|---|---|
| Браслет клиники | `ClinicBand` | Адрес и ключ валидны; метка уникальна; новый ключ из облака для известного адреса заменяет старый, прежние проверки становятся неактуальны |
| Журнал выдачи | — (коллекция `Issuance`) | У браслета не больше одной открытой выдачи; возврат позже выдачи |

## События предметной области

| Событие | Когда | Кто реагирует |
|---|---|---|
| Ключ браслета изменился | `SyncCloudBands` получил другой ключ для известного адреса (браслет перепривязан) | `bandcheck`: последняя проверка неактуальна (через `BandInventory.bands`); список отмечает браслет |
| Браслет проверен | `BandCheckLog.save` | Список и экран браслета показывают итог |
| Браслет выдан / возвращён | `IssuanceLog` | Список показывает «на руках» |

