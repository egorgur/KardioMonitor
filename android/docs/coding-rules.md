# Правила написания кода

Цель — код, который ИИ-агент и человек могут **найти, понять и безопасно изменить**,
прочитав минимум файлов. Каждое правило сопровождается причиной: если правило мешает
в конкретном случае, причина подскажет, можно ли отступить.

Структура и границы — в [architecture.md](architecture.md), термины — в
[domain-model.md](domain-model.md), тесты — в [testing.md](testing.md).

Правила, помеченные **[тест]**, проверяет `CodeRulesTest` (`src/test/.../architecture/`):
нарушение роняет `testDebugUnitTest`.

## 1. Находимость

| Правило | Почему |
|---|---|
| Имя файла = имя главного публичного типа или точки входа (`SyncHistory.kt`, `HistorySyncSection.kt`) | Агент ищет по имени файла (`Glob`) раньше, чем по содержимому |
| Один публичный тип верхнего уровня на файл. Мелкие `private`-помощники — в том же файле | Файл = единица смысла; не нужно читать 5 файлов, чтобы понять один |
| Путь пакета отражает контекст и слайс: `features.monitoring.historysync` | Путь сам отвечает на вопрос «к чему это относится» |
| Уникальные имена для разных понятий: не два класса `State` в разных пакетах | Поиск по имени возвращает одно место; меньше ошибочных импортов |

## 2. Имена

- **Из глоссария.** `ActivityMinute`, `HeartRate`, `DailySummary` — см. [domain-model.md](domain-model.md).
  Нет термина — добавьте его в глоссарий в той же задаче.
- **[тест] Запрещены пустые суффиксы** в домене и слайсах: `Manager`, `Helper`, `Util(s)`,
  `Processor`, `Handler` (кроме точек входа фреймворка), `Data`, `Info`, `Item`.
  Они ничего не говорят о назначении. Вместо `BandManager` — `BandConnection`,
  вместо `DataHelper` — конкретный глагол или понятие.
- **Сценарии — глаголом:** `SyncHistory`, `SetHeartRateMeasurementInterval`. Вызов — `operator fun invoke`.
- **Булевы — с `is/has/can/should`:** `isWorn`, `hasHeartRate`.
- **Без сокращений**, кроме общепринятых (`id`, `ui`, `db`, `mac`, `bpm`).
  `heartRate`, не `hr`; `minutes`, не `mins`.
- **Единицы измерения — в типе или имени:** `HeartRate` (уд/мин), `timeoutMs`, `intervalMinutes`.
- Идентификаторы — на английском, **комментарии и тексты интерфейса — на русском**.

## 3. Размеры

| Что | Ориентир | Что делать, если больше |
|---|---|---|
| Файл **[тест]** | ≤ 300 строк | Разделить по смыслу: состояние / UI / сценарий |
| Функция **[тест]** | ≤ 40 строк от `fun` до конца тела | Выделить шаги с говорящими именами |
| `@Composable` **[тест]** | ≤ 80 строк | Выделить `private` под-composable |
| Параметров функции | ≤ 6 | Сгруппировать в `data class` |
| Вложенность | ≤ 3 уровня | Ранний `return`, выделение функций |

Почему: агент читает файл целиком; длинный файл съедает контекст и прячет важное.

## 4. Типы вместо примитивов

```kotlin
// Плохо: что это за Int? Какой диапазон? Можно ли перепутать аргументы?
fun save(ts: Long, hr: Int?, steps: Int, kind: Int)

// Хорошо: невалидное значение не создать, перепутать аргументы нельзя
@JvmInline
value class HeartRate(val bpm: Int) {
    init { require(bpm in 11..249) { "пульс вне диапазона: $bpm" } }
}
fun save(minute: ActivityMinute)
```

- Одиночное значение с правилами → `@JvmInline value class` с проверкой в `init`.
- Составное значение → `data class` с проверкой в `init` или фабрикой в `companion`.
- Закрытый набор вариантов → `sealed interface` / `enum class`, а не `Int`/`String`-коды.
- Секреты (`AuthKey`) переопределяют `toString()`, чтобы значение не попало в лог.

## 5. Явность

- Публичные функции и свойства — **с явным типом возврата**.
- Аргументы `Boolean` и числовые литералы — **именованные**: `connect(device, autoReconnect = false)`.
- **[тест]** Без `!!`. Нужна гарантия — `requireNotNull(x) { "почему не может быть null" }`.
- **[тест]** Без `*`-импортов.
- `let/run/apply/also` — только когда упрощают чтение. Цепочки из 3+ scope-функций
  заменяйте обычными `val`.
- Магические числа → именованные константы. Протокольные константы — с источником:

```kotlin
/** Gadgetbridge HuamiService.COMMAND_SET_PERIODIC_HR_MEASUREMENT_INTERVAL */
private const val CMD_SET_HEART_RATE_INTERVAL: Byte = 0x14
```

## 6. Неизменяемость и видимость

- `val` по умолчанию; `var` — только локально и когда без него хуже.
- Публично отдаются неизменяемые коллекции (`List`, не `MutableList`) и `StateFlow`,
  не `MutableStateFlow`.
- Состояние экрана — один неизменяемый `data class XxxUiState`, обновляется через `copy`.
- Видимость — минимальная: `private` → `internal` → `public`. **[тест]** Публичное в слайсе —
  только точка входа, которую использует код вне слайса (см. architecture.md).

## 7. Ошибки

- **Ожидаемые ситуации предметной области** (браслет не найден, неверный ключ,
  нет данных) — возвращаются как `sealed interface XxxResult`.
  Вызывающий код обязан их обработать: компилятор подскажет `when`.
- **Ошибки программиста** (нарушен контракт) — `require` / `check` / `error` с
  сообщением на русском, объясняющим причину.
- **Исключения инфраструктуры** (GATT, SQLite) переводятся в доменные ошибки на
  границе — в ACL / `data`, а не в UI.
- `CancellationException` **всегда пробрасывается**: `catch (e: CancellationException) { throw e }`
  перед общим `catch (e: Exception)`.
- **[тест] Без `runCatching`** (и `Result` из него) в коде с корутинами: он перехватывает
  `CancellationException` и тихо ломает отмену. Перехватывайте конкретное исключение
  (`IOException` для GATT и файлов) и пишите в журнал.
- Таймаут ожидания браслета — сбой связи, а не отмена: `withTimeoutOrNull(…) ?: throw
  IOException(…)`, как в `GattClient.op`. `TimeoutCancellationException` из `withTimeout`
  иначе проскочит через `catch (CancellationException)` и молча завершит корутину.
- Не глотать исключения молча. Минимум — `Log.w(TAG, "что не удалось", e)`.

## 8. Корутины и потоки

- Только структурированная конкурентность: `viewModelScope`, scope из `AppContainer`
  с `SupervisorJob`, `CoroutineWorker`. **[тест] Без `GlobalScope`**.
- Блокирующий ввод-вывод (SQLite, файлы) — в `withContext(Dispatchers.IO)`.
- Callback-и Bluetooth приходят в потоке Binder: в них только перекладывание данных
  в `Channel`/`StateFlow`, никакой долгой работы и GATT-операций.
- GATT-операции — только через `GattClient` (он выстраивает их в очередь). Прямые
  вызовы `BluetoothGatt` в слайсах запрещены.
- Таймауты на всё, что ждёт браслет: `withResponseTimeout` (`platform.ble`) или
  `withTimeoutOrNull(…) ?: throw IOException(…)` — не голый `withTimeout` (§7).

## 9. Jetpack Compose

- **Поднятие состояния.** Точка входа слайса получает ViewModel; внутренний
  `XxxContent(state, onAction)` — stateless и принимает только данные и лямбды.
  Это даёт превью и UI-тесты без браслета.
- **Без бизнес-логики в composable.** Подсчёт итогов дня, фильтрация, форматирование
  смысловых значений — в домене или ViewModel. В composable — только раскладка.
- Цвета и типографика — из `MaterialTheme` и `platform.ui` (тема, `LocalChartColors`).
  **[тест]** Никаких `Color(0xFF…)` в слайсах.
- Графики: одна серия на график без легенды, заголовок называет показатель; линия 2 dp;
  выбор значения по касанию. Правила — в `platform/ui/Charts.kt`.
- Тексты — на русском, без медицинских заключений («пульс выше обычного», а не «тахикардия»).

## 10. Комментарии и документация

- Комментарий объясняет **почему**, а не что. Что — видно из кода с хорошими именами.
- KDoc обязателен для: точек входа слайсов, доменных типов, портов (`api`),
  нетривиальных протокольных функций.
- Знание о протоколе, которое нельзя вывести из кода, — со ссылкой на источник
  (файл Gadgetbridge, раздел [ble-protocol.md](ble-protocol.md)).
- Не оставлять закомментированный код и `TODO` без пояснения, что и почему.

## 11. Логирование и безопасность

- Тег — `KardioBLE` (обмен с браслетом), `KardioServer` (обмен с сервером клиники). Команды
  до 12 байт — в hex, длинные — только длина.
- **Никогда не логировать** `AuthKey`, содержимое QR-кода, учётные данные, `UploadToken`.
- Учётные данные хранятся только в приложении (SharedPreferences, позже —
  EncryptedSharedPreferences/Keystore). Не класть ключи в код, тесты (кроме тестовых
  векторов), коммиты.

## 12. Зависимости

- Новая библиотека — только с обоснованием в ADR ([adr/](adr/)) и согласованием.
  Каждая зависимость — то, что агенту нужно знать и обновлять.
- Версии фиксированы в `app/build.gradle.kts`, без `+` и диапазонов.
- DI — ручной (`AppContainer`), см. [ADR-0004](adr/0004-manual-di.md).

- [ ] Новые термины добавлены в [domain-model.md](domain-model.md)
- [ ] Правила предметной области — в доменных типах и покрыты тестами
- [ ] `./gradlew testDebugUnitTest lintDebug assembleDebug` проходит
- [ ] В логах нет секретов; `CancellationException` пробрасывается
- [ ] Обновлены документы, если изменились архитектура, протокол или решения (ADR)
