# Протокол Mi Smart Band 6 (XMSH15HM)

Знание о протоколе, которое нельзя вывести из кода. Основной источник —
[Gadgetbridge](https://codeberg.org/Freeyourgadget/Gadgetbridge) (пакет
`service/devices/huami`). Всё описанное проверено на браслете с прошивкой
**V1.0.6.10** (железо V0.82.23.3) — сначала Python-скриптами в корне репозитория,
затем этим приложением.

## Ключ авторизации

- 16 байт, выдаётся серверами Xiaomi при привязке браслета в Mi Fitness / Zepp Life.
  Создать его самостоятельно нельзя.
- Mi Fitness на Android пишет ключ в логи:
  `/sdcard/Android/data/com.xiaomi.wearable/files/log/*.log`, поле `authKey`
  (команда поиска — в корневом `README.md`).
- **Отвязка браслета в Mi Fitness или сброс браслета делают ключ недействительным.**

## Характеристики

UUID Huami: `0000XXXX-0000-3512-2118-0009af100700`, стандартные: `0000XXXX-0000-1000-8000-00805f9b34fb`.

| Код | Назначение | Свойства |
|---|---|---|
| `0x0001` | Датчики (включение для пульса) | write-no-response, notify |
| `0x0004` | Управление выгрузкой истории | write-no-response, notify |
| `0x0005` | Данные истории | notify |
| `0x0006` | Батарея: байт 1 — заряд, % | read, notify |
| `0x0007` | Шаги за сегодня: `[0x0C, шаги u32, метры u32, ккал u32]` | read, notify |
| `0x0009` | Старая авторизация | read, write-no-response, notify |
| `0x0016` / `0x0017` | Канал Huami 2021: запись / чтение (сообщения частями) | write-no-response, notify |
| `0x2A37` | Измерение пульса (стандарт BLE) | notify |
| `0x2A39` | Управление пульсом | read, write |
| `0x2A28` | Версия прошивки (Software Revision) | read |

## Авторизация Huami 2021 (прошивка 1.0.6.10+)

Старая авторизация (`0x82…` в `0x0009`) на этой прошивке отклоняется ответом
`10 83 07`, а браслет показывает «Сначала обновите приложение».

1. Сгенерировать пару ключей ECDH на кривой **NIST B-163** (`EcdhB163`, порт `ECDH_B163.java`).
   Закрытый ключ — 24 случайных байта, биты ≥ 162 обнуляются.
2. Отправить в эндпоинт `0x0082`: `04 02 00 02` + открытый ключ (48 байт, x и y по 24 байта LE).
3. Ответ: `10 04 01` + случайные 16 байт + открытый ключ браслета (48 байт).
4. Общий секрет = ECDH. Сессионный ключ = `shared[8..24] XOR authKey`.
5. Отправить `05` + `AES-ECB(random, authKey)` + `AES-ECB(random, sessionKey)`.
6. Успех: `10 05 01`. Неверный ключ: `10 05 25`.

Сообщения канала 2021 передаются частями (`ChunkedEncoder`/`ChunkedDecoder`):
первая часть `03 flags 00 handle count len(u32) endpoint(u16) данные…`,
следующие `03 flags 00 handle count данные…`. Флаги: `0x01` первая, `0x02` последняя,
`0x04` нужен ack, `0x08` зашифровано. На сообщения с флагом `0x04` нужно отвечать
`04 00 handle 01 count` в `0x0017` — **весь сеанс**, не только во время авторизации.

Тестовые векторы: `Huami2021Test` (сверены с Python и с Java-кодом Gadgetbridge).

## Пульс

| Команда в `0x2A39` | Действие |
|---|---|
| `15 02 00` | Остановить ручное измерение |
| `15 01 00` / `15 01 01` | Остановить / запустить непрерывное измерение («пульс сейчас») |
| `16` | Пинг: без него непрерывное измерение прекращается через ~15 с; слать раз в 12 с |
| `14 NN` | Частота фонового измерения, NN минут (0 — выкл, максимум 120) |

- `0x2A37`: байт 0 — флаги (бит 0 — формат uint16), далее значение. 0 — замер ещё идёт.
- На `14 NN` браслет отвечает только подтверждением записи GATT. Прочитать текущую
  частоту нельзя. Mi Fitness при подключении может перезаписать значение.

## История активности

1. `0x0004` ← `01 01` + время начала: `год(u16) месяц день час минута 00 смещение`,
   где смещение — от UTC в четвертях часа (+7 ч = `1c`).
2. Ответ `10 01 01` + количество (u32) + фактическое время начала (7 байт + смещение).
   Количество 0 — новых данных нет.
3. `0x0004` ← `02`. Данные приходят в `0x0005`: `[счётчик пакета][данные…]`, счётчик
   растёт на 1 (по модулю 256). Пропуск счётчика — порция испорчена.
4. Конец порции: `10 02 01` в `0x0004`. Порция ограничена — запрос повторяется
   с минуты после последней полученной.

Запись за минуту на Mi Band 6 — **8 байт**:
`kind, intensity, steps, heart_rate, ?, sleep, deep_sleep, rem_sleep`.

- `heart_rate` 0 или 255 — замера нет.
- `kind`: 115 — снят, 118 — заряжается, 120 — сон. Остальные коды (80, 1, 90, 16, 96,
  112 …) не расшифрованы.
- Байты сна на прошивке 1.0.6.10 выглядят служебными (`deep_sleep` всегда 128) —
  **данные о сне пока не использовать**.

### ВАЖНО: подтверждение выгрузки

Команда `03` («данные получены») заставляет браслет удалить переданную историю.
Приложение её **не отправляет** ([ADR-0002](adr/0002-keep-history-on-band.md)):
пока на телефоне есть Mi Fitness, она должна получить данные. Браслет хранит только
то, что ещё не забрала синхронизация Mi Fitness.

## Особенности Bluetooth

- Браслет держит **одно** соединение. Mi Fitness, Python-скрипты на ноутбуке и
  приложение мешают друг другу.
- Адрес браслета — random static (`E7:…`). Перед подключением приложение ищет браслет
  сканированием с фильтром по адресу, чтобы Android знал тип адреса.
- На Linux (BlueZ) браслет обрывает соединение из-за HID-сервиса: нужен
  `LEAutoSecurity=false` в `/etc/bluetooth/input.conf`. На Android такой проблемы нет.
- Android допускает одну GATT-операцию одновременно — отсюда очередь в `GattClient`.
