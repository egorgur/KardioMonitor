# ADR-0012: Секреты приложения пациента — Android Keystore

- Статус: принято и реализовано (2026-11-01)
- Дата: 2026-11-01

## Контекст

Приложение пациента хранит два долгоживущих секрета: ключ авторизации браслета и токен
загрузки на сервер клиники. Раньше оба значения лежали открытым текстом в SharedPreferences.
Нужно защитить существующие установки без потери привязки и без новой зависимости. Минимальная
версия приложения — Android 8 (API 26), а фоновая синхронизация должна работать при
заблокированном экране.

## Решение

Оба секрета шифруются AES-256-GCM одним неэкспортируемым ключом Android Keystore через
`platform.keystore.SecretBox`. IV случаен для каждой записи; в SharedPreferences хранится только
base64url-пара `IV.шифротекст`. Ключ не требует разблокированного экрана: иначе WorkManager не
сможет отправлять данные в фоне. Он остаётся неэкспортируемым и привязанным к устройству.

При первом чтении прежнего открытого поля репозиторий шифрует значение и удаляет открытое поле.
MAC, id и имя пациента, адрес сервера и настройки не являются секретами этого решения и остаются
открытыми. Потерянный ключ Keystore или повреждённый шифротекст переводят хранилище в состояние
«нужна новая привязка», но секрет не выводится в журнал. `android:allowBackup=false` сохраняется.

Реальный Keystore, неэкспортируемость ключа и потерю доступа после удаления alias проверяет
инструментальный тест на встроенном `android.test.InstrumentationTestRunner`. Перенос прежнего
значения проверяет JVM-тест `EncryptedPreferencesTest` с фейками портов. Новая AndroidX-библиотека
для тестов не добавляется.

## Последствия

- Копия SharedPreferences без исходного телефона не раскрывает ключ браслета и токен сервера.
- Обновление существующей установки переносит секреты автоматически и не требует повторного QR.
- После очистки данных, сброса защищённой блокировки или недоступности Keystore пациенту нужно
  снова отсканировать QR, чтобы получить ключ и новый токен.
- Заблокированный экран не мешает фоновой синхронизации; доступ к секрету остаётся только у
  процесса приложения через Android Keystore.

## Отвергнутые варианты

- `EncryptedSharedPreferences` — `androidx.security:security-crypto` устарела и больше не развивается.
- SQLCipher — новая нативная зависимость ради двух коротких значений.
- Удалить открытые значения без миграции — потеря действующих привязок пациентов.
- Поднять minSdk до 28 — исключает поддерживаемые телефоны Android 8.
- `setUnlockedDeviceRequired(true)` — несовместимо с фоновой синхронизацией при выключенном экране.
