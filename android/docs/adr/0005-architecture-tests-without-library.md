# ADR-0005: Архитектурные тесты на JUnit без сторонней библиотеки

- Статус: принято
- Дата: 2026-10-09

## Контекст

Правила VSA и DDD ([architecture.md](../architecture.md)) держались только на тексте.
Агент надёжнее следует падающему тесту, чем документу. В одном Gradle-модуле
`internal` виден всему модулю, поэтому видимость не мешает слайсу импортировать
другой слайс. План предусматривал Konsist, но его последний выпуск (0.17.3) вышел
в декабре 2024 года и содержит компилятор Kotlin 2.0, а проект собирается Kotlin 2.2.

## Решение

Архитектурные тесты — обычные JUnit-тесты в `src/test/java/ru/kardiomonitor/architecture/`,
разбирающие `package`, `import` и строки исходников:

- `DependencyRulesTest` — правила зависимостей из architecture.md;
- `CodeRulesTest` — механически проверяемые правила из coding-rules.md и testing.md.

Сообщение о падении называет правило, файл и строку. Тесты входят в
`testDebugUnitTest` и запускаются Stop-hook-ом агента (`.claude/hooks/`).

## Последствия

- Нарушение границ слайса ломает сборку проверки, а не ждёт ревью.
- Новой зависимости нет: агенту нечего обновлять и изучать.
- Разбор по строкам не видит семантику: правила, которым нужен синтаксический
  разбор (длина функции, «публична только точка входа»), пока проверяются ревью.
  Когда их станет важно автоматизировать — detekt отдельным ADR.
- Исключения для прототипа (`LEGACY_NAMES`) удаляются тем же шагом миграции, что
  и легаси-класс.

## Отвергнутые варианты

- Konsist — не обновлялся с 2024 года, встроенный компилятор отстаёт от проекта.
- ArchUnit — проверяет байткод JVM, плохо видит Kotlin-конструкции и пакеты-слайсы.
- Отдельные Gradle-модули на каждый слайс — избыточно для 7 слайсов (ADR-0001).
