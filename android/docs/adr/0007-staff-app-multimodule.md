# ADR-0007: Утилита персонала — второе приложение в той же Gradle-сборке, общий модуль протокола

- Статус: принято (2026-10-29)
- Дата: 2026-10-29

## Контекст

Персоналу клиники нужно отдельное Android-приложение ([staff-app/](../staff-app/README.md)):
получить ключи браслетов из облака Xiaomi, проверить браслет по BLE и показать пациенту
QR-код. Для проверки браслета нужен тот же протокол Mi Band 6, что в приложении пациента:
GATT-очередь, авторизация Huami 2021 (ECDH B-163, AES), частота пульса. Это самый
рискованный код проекта: он проверен на браслете и покрыт тестами на эталонных байтах.

ADR-0001 отверг многомодульную сборку «сразу» — для одного приложения из 7 слайсов. Теперь
причина другая: два приложения с общим кодом протокола.

## Решение

Одна Gradle-сборка `android/`, четыре модуля:

| Модуль | Тип | Что внутри |
|---|---|---|
| `:band-protocol` | Android library | `ru.kardiomonitor.platform.ble` (`GattClient`, таймауты), `ru.kardiomonitor.platform.huami` — протокол без доменных типов: `MiBand6`, `Auth2021`, `EcdhB163`, `Chunked*`, `HistoryPackets`; тесты протокола на эталонных байтах |
| `:app` | Android application `ru.kardiomonitor` | Приложение пациента; ACL `HuamiBand` и перевод записей истории в `ActivityMinute` остаются здесь |
| `:staff` | Android application `ru.kardiomonitor.staff` | Утилита персонала, свой ACL над `:band-protocol` |
| `:architecture` | Android library, только `src/test` | Архитектурные тесты (ADR-0005) для всех модулей; правила параметризованы корневым пакетом |

- `:band-protocol` не знает доменных типов приложений: `MiBand6.fetchActivity` отдаёт записи
  протокола (`ActivityRecord`: kind, intensity, steps, heart rate — байтами браслета),
  перевод в `ActivityMinute` — в ACL `:app`. Наружу из модуля — только то, что нужно
  приложениям (`public`); остальное — `internal`.
- Код протокола **переносится, а не копируется**: тесты (`Huami2021Test` и др.) едут вместе
  с ним, skill `/protocol-change` работает с `band-protocol/`.
- `:architecture` — Android library без `src/main`: новый плагин (Kotlin JVM) не нужен.
  Тесты читают исходники соседних модулей по относительным путям.
- Версии AGP, Kotlin, Compose BOM — общие, в корневом `build.gradle.kts`/каталоге версий.

## Последствия

- Исправление в протоколе сразу попадает в оба приложения; эталонные тесты — одни.
- Перенос — отдельная задача до начала кода утилиты (шаг 0 в
  [staff-app/README.md](../staff-app/README.md#план-разработки)): после него приложение
  пациента должно собираться и проходить те же тесты, данные на телефоне пациента не
  меняются (`applicationId`, база, SharedPreferences — прежние).
- `internal` больше не «виден всему коду»: граница `:band-protocol` проверяется
  компилятором, а не только архитектурными тестами.
- Сборка дольше на время конфигурации трёх модулей; для проекта такого размера — секунды.

## Отвергнутые варианты

- Отдельный Gradle-проект `staff/` с копией протокола — две копии кода авторизации, исправление
  легко забыть во второй; эталонные тесты пришлось бы дублировать.
- Composite build (`includeBuild("../android")`) — сложнее в настройке и для агента, выигрыша
  перед модулями одной сборки нет.
- Режим «сотрудника» внутри приложения пациента — ключи всех браслетов клиники и сеанс
  аккаунта Xiaomi оказались бы в APK, который ставится пациентам.
