# ADR-0001: Vertical Slice Architecture + DDD

- Статус: принято
- Дата: 2026-10-09

## Контекст

Приложение развивается в основном ИИ-агентом. Агенту нужно находить весь код
сценария в одном месте и менять его, не задевая другие сценарии. Предметная область
(кардиореабилитация) будет расти: целевые зоны пульса, тренировки, обмен с врачом.

## Решение

Код организуется по ограниченным контекстам (`features.band`, `features.monitoring`)
и внутри них — по вертикальным слайсам, по одному на пользовательский сценарий.
Правила предметной области живут в доменных типах (value objects, агрегаты) на языке
из [domain-model.md](../domain-model.md). Протокол браслета изолирован
антикоррупционным слоем в `platform.huami`. Подробно — [architecture.md](../architecture.md).

## Последствия

- Для задачи достаточно прочитать один слайс и домен его контекста.
- Небольшое дублирование между слайсами допустимо; общий код выносится, когда
  дублирование стало реальным.
- Текущий прототип не соответствует структуре — нужна поэтапная миграция.

## Отвергнутые варианты

- Слои `ui/ data/ domain/` на всё приложение — сценарий размазан по трём папкам,
  изменения задевают чужой код.
- Многомодульная структура Gradle сразу — избыточно для 7 слайсов, замедляет сборку.
