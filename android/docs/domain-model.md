# Модель предметной области

Единый язык (ubiquitous language) проекта. **Имена в коде берутся из этой таблицы.**
Если для нового понятия нет термина — сначала добавьте его сюда, потом пишите код.

Предметная область: наблюдение за пациентами в кардиореабилитации после инфаркта
миокарда по данным фитнес-браслета Mi Smart Band 6. Band 9 пока имеет только
read-only foundation, не клинический мониторинг (ADR-0014).

> Данные браслета — бытовые, не медицинские. Приложение показывает динамику и
> не ставит диагнозов. Тексты интерфейса не должны звучать как медицинское заключение.

## Глоссарий

### Контекст «Мониторинг» (`features.monitoring`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Минута активности | `ActivityMinute` | Value Object | Запись браслета за одну минуту: время начала, шаги, пульс (может отсутствовать), тип активности, интенсивность. Неизменяемая. Ключ — время начала минуты |
| Пульс | `HeartRate` | Value Object (`value class`, уд/мин) | Допустимо 11–249. Значения 0 и 255 от браслета означают «замера нет» → `null`, а не `HeartRate` (`HeartRate.fromMeasurement`) |
| Шаги | `StepCount` | Value Object | Неотрицательное целое |
| Тип активности | `ActivityKind` | `sealed interface` | `NotWorn` (код 115 — браслет снят), `Charging` (118), `Sleep` (120), `Other(code)`. Коды — деталь протокола, известны ACL (`ActivityRecords`) и формату базы (`monitoring.data.ActivityKindCodes`: история прототипа хранится кодами) |
| Интенсивность | `Intensity` | Value Object | Сырое значение браслета 0–255, смысл не расшифрован — не интерпретировать |
| История активности | `ActivityHistory` | Repository (интерфейс) | Все сохранённые минуты активности. Операции: `save(minutes)`, `minutesOf(day)`, `lastRecordedMinute()`, `changes: Flow` |
| Источник данных активности | `ActivitySource` | Порт (интерфейс в `domain`) | Браслет на языке мониторинга: `minutesSince(start)`, `liveHeartRate()`, `stepsToday()`. Реализует ACL `platform.huami.HuamiBand`. Только при открытом соединении: выгрузка — в `withSession`/`withOpenSession`, потоки — пока сеанс подключён (см. architecture.md) |
| Итоги дня | `DailySummary` | Value Object (производный) | Для набора минут одного дня: сумма шагов, пульс ср/мин/макс (среднее округляется вниз), покрытие пульсом, минуты без браслета (`NotWorn` и `Charging`). Создаётся `DailySummary.of(minutes)` |
| Покрытие пульсом | `heartRateCoveragePercent` | свойство `DailySummary` | Доля записанных минут дня, в которых есть пульс, 0–100 % |
| Синхронизация истории | `SyncHistory` | Сценарий | Выгрузка минут с браслета начиная с `HistorySyncStart` и сохранение в `ActivityHistory`; итог — в `SyncSettings.lastSync` |
| Начало выгрузки | `HistorySyncStart` | Правило (`object`) | Минута после `lastRecordedMinute()`; при первой синхронизации — за 7 дней. Не раньше минуты привязки браслета ([ADR-0011](adr/0011-band-reissue-keeps-key.md)). В часовом поясе телефона |
| Результат синхронизации | `SyncResult` | `sealed interface` (слайс `historysync`) | `Downloaded(minutes)` или `Failed(reason)`; даёт текст итога |
| Итог синхронизации | `LastSync` | Value Object | Время, итог для пользователя («загружено 30 мин», «ошибка: …»), фоновая ли синхронизация |
| Настройки синхронизации | `SyncSettings` | Repository (интерфейс) | Включена ли фоновая синхронизация (по умолчанию да) и итог последней синхронизации. Сбрасываются, когда браслет отвязан |
| Фоновая синхронизация | `HistorySyncWorker` | Точка входа слайса | Синхронизация истории по расписанию раз в 30 минут |
| Короткое обновление истории | `ActivityHistoryRefresh` | Порт (`api`) | Попытка фоновой синхронизации для локального сценария; возвращает, удалось ли обновить данные |
| Попытка синхронизации завершена | `HistorySyncEvents` | Порт (интерфейс в `domain`) | Событие после каждой попытки `SyncHistory` в `finally`: с новыми минутами, без них и после сбоя. По нему телефон забирает запрос пульса клиники |
| Пульс сейчас | `liveheartrate` | Слайс | Непрерывное ручное или запрошенное клиникой измерение. Единственный `LiveHeartRateMeasurement` владеет потоком BLE; режимы не конкурируют. Ручной держит открытое соединение, клинический работает в фоновом сеансе |
| Событие «пульс сейчас измерен» | `LiveHeartRateFeed`, `LiveHeartRateReading` | Порт (интерфейс в `domain`) | Слайс `liveheartrate` публикует каждое значение с моментом получения; подписчики (передача врачу) не запускают второе измерение. Реализация — `InMemoryLiveHeartRateFeed`: медленный подписчик теряет старые значения |
| Запрос пульса клиники | `LiveHeartRateRequest` | Aggregate root | Один устойчивый запрос: id, 1–60 мин, срок, локальное начало, состояние и упорядоченный outbox отчётов. После перезапуска выполняется только оставшееся время; повтор не запускает второй поток |
| Выполнение запроса пульса | `RequestedLiveHeartRateWorker` | Точка входа слайса | Long-running `CoroutineWorker`, foreground type `connectedDevice`; до BLE требует CDM-ассоциацию и видимое уведомление, пациент может остановить действием уведомления |
| Минуты после момента | `ActivityHistory.minutesAfter(after, limit)` | метод репозитория | До `limit` минут позже `after` (null — с начала истории), по порядку. Для отправки врачу |
| Шаги сегодня | `stepstoday` | Слайс | Счётчик шагов за сегодня с браслета (0x0007), пока он подключён. Отличается от суммы шагов истории: история приходит при синхронизации |

### Контекст «Браслет» (`features.band`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Браслет | `Band` | Aggregate root | Браслет пациента: учётные данные, момент привязки + заданные приложением настройки. `Band.paired(credentials, at)` — новая привязка без настроек |
| Хранилище браслета | `BandRepository` | Repository (интерфейс) | Привязанный браслет (`band: StateFlow<Band?>`, null — не привязан), `save`, `forget` |
| Адрес браслета | `BandAddress` | Value Object | MAC в формате `AA:BB:CC:DD:EE:FF`, верхний регистр |
| Ключ авторизации | `AuthKey` | Value Object | 16 байт. **Секрет**: `toString()` не раскрывает значение, ключ не логируется |
| Учётные данные браслета | `BandCredentials` | Value Object | Адрес + ключ + явный протокол. Новая выдача QR v3; старые QR/привязки без protocol — Band 6, неизвестный protocol отвергается — [qr-contract.md](qr-contract.md). Ключ зашифрован Android Keystore (ADR-0012) |
| Протокол браслета | `BandProtocol` | Enum | `MiBand6Ble` / `XiaomiBand9Spp`. Не определяется по имени или форме ключа. Непроверенные Xiaomi monitoring/SET запрещены |
| Прочитанные настройки пульса | `ReportedHeartRateSettings` | Value Object | Независимые nullable disabled и intervalMinutes; у Xiaomi 0 = Smart, не Off. Список допустимых SET-интервалов из ответа не выводится |
| Привязка браслета | `pairing` | Слайс | Ввод учётных данных (QR или вручную) с запоминанием момента привязки и их удаление («Сменить браслет»). QR v2 сначала привязывает телефон к пациенту клиники |
| Момент привязки | `Band.pairedAt`, `BandPairing` | свойство агрегата / порт (`api`) | Когда пациент привязал браслет. История браслета раньше — чужая: браслет выдаётся повторно с тем же ключом ([ADR-0011](adr/0011-band-reissue-keeps-key.md)). null — привязан до версии, которая его запоминает. `BandPairing` реализует `StoredBandPairing` (слайс `pairing`), читает синхронизация истории |
| Системная ассоциация браслета | `BandAssociation`, `CompanionBandAssociation` | Порт / реализация слайса | Обычная подтверждаемая пациентом Companion Device Manager association по точному MAC. Даёт разрешённую Android причину фонового `connectedDevice` FGS; self-managed не используется (ADR-0013) |
| Сеанс связи | `BandConnection` | Порт (`api`) | Установленное и авторизованное соединение. **Одно на всё приложение**: браслет держит одно соединение. Реализация — `SingleBandConnection` (слайс `connection`). `withSession` (подключается сам), `withOpenSession` (только открытое), `holdOpen` (не закрывать при сворачивании до конца измерения) |
| Состояние сеанса | `ConnectionState` | Value Object (`api`) | Стадия, фоновый ли сеанс, заряд, записанная в браслет частота пульса, проблема |
| Стадия подключения | `ConnectionStage` | `enum` | `Disconnected`, `Searching`, `Connecting`, `Authenticating`, `Connected` |
| Проблема связи | `ConnectionProblem` | `sealed interface` | Почему сеанса нет или он неполный: не привязан, не подключён (`NotConnected` — для действий с экрана), нет Bluetooth / разрешения, не найден, авторизация отклонена, сбой связи, соединение потеряно, настройка не записана |
| Результат подключения | `OpenResult` | `sealed interface` | `Opened` или `Refused(problem)` — ответ `BandLink.open`; ошибки GATT и разбора ответов переводит в него ACL |
| Канал связи | `BandLink` | Порт (интерфейс в `domain`) | Открыть/закрыть соединение с авторизацией, прочитать заряд, записать частоту пульса. Реализует ACL `platform.huami.HuamiBand`; пользуется только `SingleBandConnection` |
| Частота измерения пульса Band 6 | `HeartRateMeasurementInterval` | Value Object | `Off` или 1–120 минут. В интерфейсе Band 6: 1, 5, 10, 30 мин, «Выкл». Приложение хранит выбор и записывает при подключении Band 6. Для Band 9 назначение и отправка запрещены (ADR-0014) |
| Заряд браслета | `BatteryLevel` | Value Object | 0–100 %. Сохраняется при каждом подключении для оценки расхода |
| Журнал заряда | `BatteryLog` | Repository (интерфейс) | Заряд при каждом подключении (таблица `battery`) |

### Контекст «Обмен с клиникой» (`features.clinic`)

Сервер клиники — `../backend` (для демо — ноутбук + ngrok). Термины совпадают с
`backend/docs/domain-model.md`.

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Адрес сервера | `ServerAddress` | Value Object | `http(s)://хост[:порт][/путь]`, без `/` в конце; без схемы — `https`. Вводится в приложении (адрес ngrok) |
| Имя пациента | `PatientName` | Value Object | Как показать пациента врачу: 1–100 знаков, без пробелов по краям |
| Токен загрузки | `UploadToken` | Value Object | **Секрет** от сервера для `Authorization: Bearer`. `toString()` не раскрывает значение, не логируется |
| Код привязки | `EnrollmentCode` | Value Object | Одноразовый 22-символьный base64url-код из QR v2, действует 72 часа; `toString` не раскрывает значение |
| Привязка к клинике | `ClinicEnrollment`, `EnrollmentResult` | Порт / результат | Обменивает код на токен пациента и заменяет прежнюю регистрацию. Неверный, использованный или истёкший код — ожидаемый результат |
| Регистрация на сервере | `ServerRegistration` | Value Object | Адрес, id пациента на сервере, имя, токен. `ServerRegistrationRepository` (SharedPreferences `clinic_server`); токен зашифрован Android Keystore (ADR-0012); null — данные никуда не отправляются |
| Сервер клиники | `ClinicServer` | Порт (интерфейс в `domain`) | Регистрация, минуты, пульс, план, оповещения и запросы непрерывного пульса. Реализация — `HttpClinicServer`; сбои — `IOException` |
| Запрос пульса для телефона | `PhoneLiveHeartRateRequest`, `LiveHeartRateRequestStatusReport` | Wire value objects | Контракт GET активного запроса и PUT состояния. Слайс мониторинга переводит их в свой устойчивый агрегат; `clinic` не запускает BLE и WorkManager |
| Минута для сервера | `MinuteReport`, `ReportedKind` | Value Object | `ActivityMinute` на языке API: тип названием (`not_worn`, `charging`, `sleep`, `other`), код браслета — только для `other` |
| Отправка врачу | `UploadNewMinutes`, `MinuteUploader` | Сценарий / точка входа | Сервер говорит, какую минуту принял последней; телефон отправляет следующие пакетами по суткам. Запуск — после каждого пополнения истории и после регистрации |
| Передача пульса сейчас | `LiveHeartRateSharing` | Точка входа | Каждое значение `LiveHeartRateFeed` уходит на сервер, пока телефон зарегистрирован. Сбой — пропуск значения |

## Агрегаты и инварианты

| Агрегат | Корень | Инварианты |
|---|---|---|
| Браслет | `Band` | Учётные данные валидны (адрес и ключ проходят проверку). Частота измерения — из допустимого диапазона. Смена учётных данных сбрасывает настройки и задаёт новый момент привязки |
| История активности | — (коллекция `ActivityMinute`) | Одна запись на минуту (повторная выгрузка перезаписывает). Минуты не изменяются после записи |
| План реабилитации | `RehabPlan` | Есть хотя бы одна версия; версии уникальны и упорядочены по `effectiveFrom`; программа полностью покрыта этапами |

## События предметной области

| Событие | Когда | Кто реагирует |
|---|---|---|
| История пополнилась | `ActivityHistory.save` записал новые минуты | Итоги дня перечитывают день (через `ActivityHistory.changes`) |
| Браслет подключён кнопкой | `BandConnection.state` → `Connected`, не фоновый | Синхронизация истории выгружает новые минуты |
| Браслет отвязан | Пользователь нажал «Сменить браслет» (`BandRepository.band` → null) | Фоновая синхронизация снимается с расписания, настройки синхронизации сбрасываются (`app/BackgroundSyncSchedule`) |
| История пополнилась (для клиники) | `ActivityHistory.changes` | `clinic.minuteupload.MinuteUploader` отправляет новые минуты врачу |
| Пульс сейчас измерен | `LiveHeartRateFeed.publish` (слайс `liveheartrate`) | `clinic.liveheartrateshare.LiveHeartRateSharing` отправляет значение на сервер |
| История пополнилась (для реабилитации) | `ActivityHistory.changes` | `rehab.plansync.RehabPlanSynchronizer` проверяет новую версию плана; экран пересчитывает прогресс локально |
| Пациент клиники изменился | `ServerRegistrationRepository.registration` | Выбирается принадлежащий пациенту кэш и загружается его текущий план |
| Отправка минут врачу завершена | `ClinicSyncEvents.minuteUploadCompleted` | Синхронизация оповещений забирает новые и изменённые записи сервера |

## Карта контекстов

```
 ┌──────────────────────┐   ActivityHistory.changes,   ┌───────────────────────┐
 │  Обмен с клиникой    │   LiveHeartRateFeed          │  Мониторинг           │
 │  (clinic), supporting│ ◄─────────────────────────── │  (monitoring), core   │
 └─────────┬────────────┘   (доменные типы и события)  └──────────┬────────────┘
           │ JSON API v1 (backend/docs/api-contract.md)           │ BandConnection (api)
           ▼                                                      ▼
 ┌──────────────────────┐                              ┌───────────────────────┐
 │  Сервер клиники      │                              │  Браслет (band)       │
 │  (../backend)        │                              │  supporting           │
 └──────────────────────┘                              └──────────┬────────────┘
                                                                  │ ACL: HuamiBand переводит
                                                                  ▼ байты в доменные типы
 ┌──────────────────────┐   ACL: RehabActivityMinute   ┌───────────────────────┐
 │  Реабилитация        │ ◄─────────────────────────── │  Мониторинг           │
 │  (rehab), core       │   + история по часовому поясу│                       │
 └─────────▲────────────┘                              └───────────────────────┘
           │ GET /api/v1/me/rehab-plan
           │ через контекст clinic
```

Мониторинг тоже видит протокол только через ACL: порт `ActivitySource` реализует `HuamiBand`.

## Как добавлять понятия

1. Новый термин → строка в глоссарии (термин, имя в коде, тип, правила).
2. Правило предметной области → метод или `init` доменного типа + тест, названный
   на языке предметной области.
3. Значение из протокола (байт, код) → константа в `platform.huami` со ссылкой на
   источник и перевод в доменный тип в ACL.
