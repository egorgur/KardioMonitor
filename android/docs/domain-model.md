# Модель предметной области

Единый язык (ubiquitous language) проекта. **Имена в коде берутся из этой таблицы.**
Если для нового понятия нет термина — сначала добавьте его сюда, потом пишите код.

Предметная область: наблюдение за пациентами в кардиореабилитации после инфаркта
миокарда по данным фитнес-браслета Mi Smart Band 6.

> Данные браслета — бытовые, не медицинские. Приложение показывает динамику и
> не ставит диагнозов. Тексты интерфейса не должны звучать как медицинское заключение.

## Глоссарий

### Контекст «Мониторинг» (`features.monitoring`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Минута активности | `ActivityMinute` | Value Object | Запись браслета за одну минуту: время начала, шаги, пульс (может отсутствовать), тип активности, интенсивность. Неизменяемая. Ключ — время начала минуты |
| Пульс | `HeartRate` | Value Object (`value class`, уд/мин) | Допустимо 11–249. Значения 0 и 255 от браслета означают «замера нет» → `null`, а не `HeartRate` |
| Шаги | `StepCount` | Value Object | Неотрицательное целое |
| Тип активности | `ActivityKind` | `sealed interface` | `NotWorn` (код 115 — браслет снят), `Charging` (118), `Sleep` (120), `Other(code)`. Коды — деталь протокола, известны только ACL |
| Интенсивность | `Intensity` | Value Object | Сырое значение браслета 0–255, смысл не расшифрован — не интерпретировать |
| История активности | `ActivityHistory` | Repository (интерфейс) | Все сохранённые минуты активности. Операции: `save(minutes)`, `minutesOf(day)`, `lastRecordedMinute()`, `changes: Flow` |
| Итоги дня | `DailySummary` | Value Object (производный) | Для набора минут одного дня: сумма шагов, пульс ср/мин/макс, покрытие пульсом, минуты без браслета. Создаётся `DailySummary.of(minutes)` |
| Покрытие пульсом | `heartRateCoverage` | свойство `DailySummary` | Доля минут дня, в которых есть пульс, 0–100 % |
| Синхронизация истории | `SyncHistory` | Сценарий | Выгрузка минут с браслета начиная с минуты после `lastRecordedMinute()` (при первом запуске — за 7 дней) и сохранение в `ActivityHistory` |
| Фоновая синхронизация | `HistorySyncWorker` | Точка входа слайса | Синхронизация истории по расписанию раз в 30 минут |
| Пульс сейчас | `LiveHeartRate` | Слайс | Непрерывное измерение по запросу пользователя (для тренировок). Значение каждые 2–3 с; поддерживается пингом раз в 12 с |

### Контекст «Браслет» (`features.band`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Браслет | `Band` | Aggregate root | Браслет пациента: учётные данные + заданные приложением настройки |
| Адрес браслета | `BandAddress` | Value Object | MAC в формате `AA:BB:CC:DD:EE:FF`, верхний регистр |
| Ключ авторизации | `AuthKey` | Value Object | 16 байт. **Секрет**: `toString()` не раскрывает значение, ключ не логируется |
| Учётные данные браслета | `BandCredentials` | Value Object | Адрес + ключ. Выдаются клиникой в QR-коде `kardio;<MAC>;<ключ>` |
| Привязка браслета | `pairing` | Слайс | Ввод учётных данных (QR или вручную) и их удаление («Сменить браслет») |
| Сеанс связи | `BandConnection` | Порт (`api`) | Установленное и авторизованное соединение. **Одно на всё приложение**: браслет держит одно соединение |
| Частота измерения пульса | `HeartRateMeasurementInterval` | Value Object | `Off` или 1–120 минут. В интерфейсе: 1, 5, 10, 30 мин, «Выкл». Браслет не сообщает текущее значение — приложение хранит выбор и записывает его при каждом подключении |
| Заряд браслета | `BatteryLevel` | Value Object | 0–100 %. Сохраняется при каждом подключении для оценки расхода |

### Планируемый контекст «Реабилитация» (`features.rehab`)

Термины согласовать с врачом-реабилитологом **до** написания кода:
целевая зона пульса, тренировка (занятие ЛФК), превышение зоны, пульс покоя.

## Агрегаты и инварианты

| Агрегат | Корень | Инварианты |
|---|---|---|
| Браслет | `Band` | Учётные данные валидны (адрес и ключ проходят проверку). Частота измерения — из допустимого диапазона. Смена учётных данных сбрасывает настройки |
| История активности | — (коллекция `ActivityMinute`) | Одна запись на минуту (повторная выгрузка перезаписывает). Минуты не изменяются после записи |

## События предметной области

| Событие | Когда | Кто реагирует |
|---|---|---|
| История пополнилась | `ActivityHistory.save` записал новые минуты | Итоги дня перечитывают день (через `ActivityHistory.changes`) |
| Браслет отвязан | Пользователь нажал «Сменить браслет» | Фоновая синхронизация снимается с расписания |

## Карта контекстов

```
 ┌──────────────────────┐   BandConnection (api)   ┌───────────────────────┐
 │  Браслет (band)      │ ◄─────────────────────── │  Мониторинг           │
 │  supporting          │                          │  (monitoring), core   │
 └─────────┬────────────┘                          └──────────┬────────────┘
           │ ACL: HuamiBand переводит байты в доменные типы    │
           ▼                                                  ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │  Протокол Huami / Mi Band 6 (platform.huami) — чужая модель            │
 └────────────────────────────────────────────────────────────────────────┘
```

## Как добавлять понятия

1. Новый термин → строка в глоссарии (термин, имя в коде, тип, правила).
2. Правило предметной области → метод или `init` доменного типа + тест, названный
   на языке предметной области.
3. Значение из протокола (байт, код) → константа в `platform.huami` со ссылкой на
   источник и перевод в доменный тип в ACL.
