## Что ревьюить

Изменения относительно последнего коммита в `android/`:

```bash
git diff HEAD -- .
git status --porcelain -- .
```

Новые (неотслеживаемые) файлы прочитать целиком.

## По каким правилам

Прочитать: `docs/architecture.md`, `docs/domain-model.md`, `docs/coding-rules.md`,
`docs/testing.md`. Если затронут протокол — `docs/ble-protocol.md`.

Механические правила проверяют `DependencyRulesTest` и `CodeRulesTest` — их не
дублировать. Но **любое изменение в `src/test/.../architecture/`, ослабляющее правило
или добавляющее исключение, — блокер**, если в том же диффе нет согласованной правки
architecture.md или coding-rules.md.

Проверять то, что тесты не видят:

- Правило предметной области в ViewModel, сценарии или composable вместо доменного
  типа; анемичная модель; `if` про предметную область в сценарии.
- Примитивы вместо value-типов (`Int` для пульса, `String` для MAC), int-коды вместо `sealed`.
- Имена не из глоссария; новый термин не добавлен в `domain-model.md`.
- Чужой `UiState`; бизнес-логика в composable.
- Больше 6 параметров, вложенность > 3. (Длину функций и «публична только точка входа»
  проверяют `CodeRulesTest` и `DependencyRulesTest`.)
- `CancellationException` проглатывается; исключение глотается без журнала; таймаут
  браслета через `withTimeout` без перевода в `IOException`.
- Секреты в журнале, тестах, коде; отправка `03` браслету; второй `GattClient`.
- Тесты: проверяют вызовы, а не результат; моки вместо фейков; протокол без эталонных байтов.
- Абстракции «на будущее»: `BaseViewModel`, `UseCase<In, Out>`, `Repository<T>`.
- Документы не обновлены (глоссарий, протокол, ADR, карта слайсов).
