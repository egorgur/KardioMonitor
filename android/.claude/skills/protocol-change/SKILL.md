# Изменение протокола браслета

Ошибка в байтах не видна в тестах без эталона и проявляется только на браслете
пациента. Поэтому порядок жёсткий.

## Шаги

1. **Прочитать** `docs/ble-protocol.md` и ADR-0002 (не отправлять `03`), ADR-0003
   (одно соединение).
2. **Найти эталон.** Проверенная на браслете Python-реализация в корне репозитория
   (`../huami2021.py`, `../fetch_history.py`, `../miband6_poc.py`) или исходник
   Gadgetbridge (`service/devices/huami`). Без эталона — остановиться и спросить человека.
3. **Получить векторы скриптом, не вручную.** Запустить эталонную функцию через
   `../.venv/bin/python -c '…'` с фиксированными входами. Ключ — только тестовый
   `00112233445566778899aabbccddeeff`, никогда настоящий. Команду генерации записать
   в KDoc теста.
4. **Падающий тест** с векторами — рядом с кодом протокола (`src/test/.../ble/`, после
   миграции `platform/huami/`), как `Huami2021Test`.
5. **Реализация.** Константы — именованные, с источником в KDoc
   (`/** Gadgetbridge HuamiService.COMMAND_… */`). Байты протокола не выходят за ACL:
   наружу — доменные типы. GATT — только через `GattClient`; ошибки связи — `IOException`.
6. **Журнал.** Тег `KardioBLE`; команды до 12 байт — в hex, длинные — только длина.
   Ключ, сессионный ключ, содержимое QR не логировать.
7. **Проверка:**
   ```bash
   ./gradlew testDebugUnitTest lintDebug assembleDebug
   ```
   и на устройстве по `docs/testing.md` («Что искать в журнале»). Нет телефона — сказать
   человеку, что проверка на браслете не выполнена, и какие строки журнала ждать.
8. **Документы.** Обновить `docs/ble-protocol.md`; новое поведение браслета — с версией
   прошивки, на которой проверено.
