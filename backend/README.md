# KardioMonitor — сервер (демо-прототип)

Принимает данные браслета с телефона пациента и показывает их на панели клиники:

```
Mi Band 6 ──BLE──► Android-приложение ──HTTPS (ngrok)──► FastAPI + SQLite ──► панель (React)
```

- **Регистрация** — пациент вводит в приложении адрес сервера и имя; сервер выдаёт токен
  загрузки, телефон шлёт его в `Authorization: Bearer`.
- **История** — после каждой синхронизации с браслетом телефон отправляет новые минуты
  (пульс, шаги, тип активности). Повтор безопасен.
- **Пульс сейчас** — пока в приложении включено «Пульс сейчас», каждое значение (раз в 2–3 с)
  уходит на сервер; панель обновляется каждые 2 с.
- **Пульс по запросу врача** (ТР-09) — панель создаёт запрос на 1–60 минут, телефон забирает его
  при следующей синхронизации и в порядке сообщает «идёт», «завершён», «остановлен пациентом»
  или причину сбоя. Пока запрос активен, второй запрос пациенту сервер не создаёт.
- **Оповещения** (ТР-08) — «высокий пульс» сервер создаёт при приёме минут и «пульса сейчас»,
  «норма дня выполнена / не выполнена» и «почти не ходит» — раз в день во время дневных
  оповещений пациента (по умолчанию 17:00 UTC, пример до ответа клиники). Врач видит их через API
  панели, телефон забирает при синхронизации (`GET /api/v1/me/alerts`). Приходят с задержкой
  синхронизации и не заменяют экстренную помощь. Индивидуальный верхний порог тренировочных
  минут (`null` по умолчанию) проверяется сразу по полному дню после приёма/исправления минут
  и при правке плана за сегодня. Первое превышение — неизменяемый снимок за день пациента.

Документация для разработки (и ИИ-агента) — [docs/](docs/README.md).

## Демонстрация: по шагам

Нужны: `uv`, Node.js 20+, [ngrok](https://ngrok.com/download) с токеном
(`ngrok config add-authtoken <токен>` — один раз), телефон с приложением и браслет.

```bash
# 1. Панель (один раз после изменений во frontend/)
cd frontend && npm install && npm run build && cd ..

# 2. Сервер — из backend/
cd backend
uv sync
cp .env.example .env
uv run python -m kardiomonitor.app.admin create-clinician doctor "Врач Демо"  # пароль спросит; один раз
uv run uvicorn kardiomonitor.app.main:create_app --factory --port 8000

# 3. Туннель — в другом терминале
ngrok http 8000               # адрес вида https://xxxx.ngrok-free.app
```

4. **Телефон:** приложение KardioMonitor → карточка «Сервер клиники» → адрес из ngrok и имя
   пациента → «Зарегистрироваться». Затем «Синхронизировать» (история уйдёт на сервер) и
   «Пульс сейчас» → «Измерять».
5. **Лечащий врач** (ТР-11: врач видит только своих пациентов) — в терминале сервера:
   ```bash
   uv run python -m kardiomonitor.app.admin patients              # идентификатор нового пациента
   uv run python -m kardiomonitor.app.admin assign <patient_id> doctor
   ```
6. **Панель:** открыть `https://xxxx.ngrok-free.app/`, войти логином и паролем врача. Ngrok
  бесплатного плана один раз покажет страницу-предупреждение — «Visit Site». В карточке
  пациента можно запросить непрерывный пульс; телефон получит запрос при следующей ручной или
  фоновой синхронизации.

Swagger API: `https://xxxx.ngrok-free.app/docs`.

### Репетиция без браслета

```bash
uv run python scripts/simulate_phone.py http://127.0.0.1:8000 --name "Демо Пациент" --live-seconds 300
```

Скрипт регистрирует пациента, отправляет историю за вчера и сегодня и «пульс сейчас»
раз в 2 с — как телефон.

## Важно

- **Адрес ngrok меняется при каждом запуске** (на бесплатном плане без статического домена):
  после перезапуска ngrok телефон нужно зарегистрировать заново («Отключиться от сервера»).
  Статический домен бесплатного плана: `ngrok http --url=<ваш-домен>.ngrok-free.app 8000`.
- **Ссылка ngrok публичная.** Панель — только после входа врача, и врач видит только своих
  пациентов; пароль врача — не короче 12 знаков. После 5 неверных паролей подряд вход закрыт на
  15 минут; `reset-password <логин>` снимает блокировку. API телефона защищён токеном загрузки.
- **База — `kardio.db` рядом с сервером** (SQLite, [ADR-0007](docs/adr/0007-sqlite-for-demo.md)).
  Существующую базу не удалять: обновление схемы описано ниже.
- Данные выдуманы или ваши собственные: это прототип, не медицинская система.

## Обновление существующей базы

Для верхнего порога тренировочных минут нужна nullable-колонка в `rehab_plan_revisions`.
Сервер при старой схеме откажется запускаться с инструкцией, но не удалит и не изменит данные.
Остановить сервер и других писателей, сделать резервную копию `kardio.db` вместе с `-wal` и
`-shm` (либо согласованную SQLite backup), сохранить прежний `KARDIO_DATABASE_URL` и выполнить
из `backend/`:

```bash
uv run python -m kardiomonitor.app.schema_upgrade
```

Команда идемпотентна: добавляет только отсутствующую колонку; пациенты, минуты, оповещения,
версии и их параметры сохраняются. У всех старых версий порог остаётся `null` (выключен).
Новая база создаётся при запуске, отдельное обновление ей не нужно. Обновление не запускается
автоматически; перед откатом к старому коду восстановление выполнять из резервной копии.
