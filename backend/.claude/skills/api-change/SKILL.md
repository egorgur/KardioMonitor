# Изменение контракта API

Приложение нельзя обновить на всех телефонах одновременно: старые версии работают с новым
сервером. Ошибка в контракте проявляется на телефоне пациента, а не в тестах сервера.

## Шаги

1. **Прочитать** `docs/api-contract.md` целиком: общие правила, коды ошибок, «Правила
   изменения контракта».
2. **Классифицировать изменение.**
   - Совместимое (новый эндпоинт, необязательное поле запроса, поле ответа, новый `code`,
     ослабление ограничения) — продолжать.
   - Несовместимое (удалить/переименовать поле, эндпоинт или `code`; сделать поле
     обязательным; сменить тип или смысл; ужесточить ограничение; сменить статус успеха) —
     **остановиться**: только `v2` рядом с `v1`, с ADR, планом обновления Android и
     согласием человека.
3. **Описать** изменение в `docs/api-contract.md` (таблица полей, пример JSON, коды ошибок)
   до кода.
4. **Тест первым** в `tests/features/<контекст>/<слайс>/`: новое поведение и то, что
   старый запрос (без нового поля) по-прежнему проходит.
5. **Схемы и перевод** — `schemas.py` слайса (`…In`/`…Out`, `to_domain`/`from_domain`).
   Правило с собственным `code` — в домене, не в `Field` (coding-rules.md §10).
6. **Снимок OpenAPI:**
   ```bash
   uv run python -m kardiomonitor.app.export_openapi > tests/contract/openapi.json
   git diff tests/contract/openapi.json
   ```
   Прочитать дифф: в нём только задуманное. Лишнее (переименованный `operationId`,
   поменявшийся тип) — исправить код, не снимок.
7. **Клиенты.** Android: `../android/app/src/main/java/ru/kardiomonitor/features/clinic/data/ClinicJson.kt`
   и `ClinicJsonTest` — если телефон отправляет или читает поле. Панель: `../frontend/src/api.ts`.
   Изменения в другом проекте — согласовать с человеком, если они не входят в задачу.
8. **Проверка:** `./scripts/check.sh`; для эндпоинтов телефона — `scripts/simulate_phone.py`.
9. **Ревью** — подагент `architecture-reviewer`.
