# ADR-0002: Стек — FastAPI, Pydantic v2, SQLAlchemy 2 async, PostgreSQL, Alembic, uv

- Статус: принято частично — для демо-прототипа база SQLite без Alembic (ADR-0007),
  DI — dishka (ADR-0003); PostgreSQL и Alembic — перед реальными пациентами
- Дата: 2026-10-16

## Контекст

Нужен HTTP-сервер для приёма поминутных данных браслетов (около 1 440 записей на
пациента в сутки) и выдачи их клинике. Язык — Python (на нём написан прототип протокола
в корне репозитория). Стек должен быть распространённым — агент лучше знает популярные
библиотеки — и типизированным, чтобы mypy ловил ошибки до запуска.

## Решение

| Что | Выбор |
|---|---|
| Язык | Python 3.13 |
| Пакеты и окружение | uv, `pyproject.toml` + `uv.lock` |
| Веб-фреймворк | FastAPI (с `Depends(scope=...)`, см. ADR-0005), сервер — Uvicorn |
| Схемы API и настройки | Pydantic v2, pydantic-settings |
| База | PostgreSQL |
| Доступ к базе | SQLAlchemy 2.0 (asyncio) + asyncpg |
| Миграции | Alembic |
| Тесты | pytest, pytest-asyncio, httpx (`ASGITransport`) |
| Качество | ruff (линтер и форматтер), mypy strict, import-linter |

## Последствия

- Один язык с Python-прототипом протокола; агент хорошо знает каждый инструмент.
- PostgreSQL нужен и для тестов репозиториев (docker compose).
- При росте объёма истории — рассмотреть партиционирование таблицы минут или
  TimescaleDB (новым ADR, по измерениям).

## Отвергнутые варианты

- Django + DRF — ORM и админка не нужны, синхронная модель хуже подходит для множества
  мелких загрузок с телефонов.
- SQLModel — смешивает схемы API и таблицы, что противоречит разделению домена, схем и
  хранения (ADR-0004).
- SQLite — нет параллельной записи и `timestamptz`; другая семантика в тестах и на сервере.
- Poetry / pip-tools — uv быстрее и покрывает окружение, lock-файл и запуск.
