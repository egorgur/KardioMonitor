# ADR-0008: Контексты «Реабилитация», «Оповещения», «Доступ» и слои между контекстами

- Статус: принято (2026-10-29)
- Дата: 2026-10-29

## Контекст

Требования клиники ([docs/requirements.md](../../../docs/requirements.md)) добавляют нормы и
программу реабилитации, тренировочные минуты, прогресс, оповещения, аккаунты врачей и карточку
пациента. Положить их в «Мониторинг» — значит смешать сырые данные браслета с решениями врача:
контекст вырастет, а правила норм будут зависеть от деталей приёма минут. Нужны новые границы и
правило, кто от кого зависит, чтобы не появились циклы.

## Решение

- **Реабилитация** `features.rehab` (основной): программа `RehabPlan` с версиями, этапы, нормы
  дня, параметры наблюдения; правила тренировочной минуты, выполнения нормы, прогресса.
- **Оповещения** `features.alerts` (поддерживающий): журнал `PatientAlert`, проверки, доставка
  врачу и пациенту.
- **Доступ** `features.access` (общий): врачи, вход, сеансы, журнал доступа.
- Распределение пульса и запрос «пульса сейчас» остаются в «Мониторинге»: норм пациента в них нет.
- Контексты образуют слои `alerts → rehab → monitoring → patients → access`. Контекст
  импортирует домен и `api.py` только нижележащих. Нижнему нужна реакция верхнего — порт в домене
  нижнего, реализация в верхнем, связывает `app` (ADR-0009). Слои проверяет import-linter;
  контекст входит в контракт, когда появляется его пакет.

## Последствия

- Нет циклов между контекстами; правка норм не трогает приём минут.
- «Пациенты» получают тип `ClinicianId` из домена «Доступа» (лечащий врач), «Доступ» не знает
  пациентов: его журнал хранит идентификатор объекта без типа пациента.
- Экран, которому нужны данные нескольких контекстов (список пациентов ТР-06), собирает панель из
  ответов каждого контекста (UI composition), а не отдельный «контекст панели».

## Отвергнутые варианты

- Всё в «Мониторинге» — смешение данных браслета и решений врача, один контекст на весь сервер.
- Оповещения внутри «Реабилитации» — у них своя жизнь (журнал, просмотр, доставка) и свои
  триггеры, включая «высокий пульс», который от норм не зависит.
- Лечащий врач в «Доступе» (таблица назначений) — список пациентов врача с поиском по ФИО
  потребовал бы соединять данные двух контекстов; у пациента один лечащий врач, это его атрибут.
