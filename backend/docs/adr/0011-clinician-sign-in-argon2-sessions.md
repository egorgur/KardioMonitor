# ADR-0011: Вход врача — пароль с Argon2id, сеанс в cookie, журнал доступа

- Статус: принято (зависимость `argon2-cffi` разрешена человеком 2026-10-29)
- Дата: 2026-10-29

## Контекст

ТР-11 ([docs/requirements.md](../../../docs/requirements.md)): у каждого врача свой аккаунт, врач
видит только своих пациентов, общий ключ панели больше не открывает данные. Решено 2026-10-29 (В-23) —
вход по логину и паролю, аккаунты создаёт администратор командой на сервере, сеанс 8 ч, других
ролей нет. Панель и API — с
одного адреса (ngrok), панель — React-приложение в браузере.

## Решение

- **Пароль** — не короче 12 знаков (до 128), хранится только хешем **Argon2id** библиотекой
  [`argon2-cffi`](https://argon2-cffi.readthedocs.io/) с её параметрами по умолчанию (профиль
  RFC 9106 «low memory»). Порт `PasswordHasher` — в домене «Доступа», реализация — в `data/`.
  Неизвестный логин проверяется против заранее вычисленного хеша: время ответа не выдаёт,
  есть ли такой логин.
- **Блокировка:** 5 неудачных попыток подряд — вход врача закрыт на 15 минут (`429`); удачный вход
  обнуляет счётчик. Ответ на неверный логин и неверный пароль одинаковый (`401 invalid_credentials`).
- **Сеанс** — случайный токен 256 бит в cookie `kardio_session`: `HttpOnly`, `Secure`,
  `SameSite=Strict`, `Path=/api`. В базе — только SHA-256 токена (как `UploadToken`). Истекает
  через 8 ч без запросов; «Выйти» удаляет его на сервере. Время последнего запроса обновляется
  не чаще раза в 5 минут.
- **Сеансы пишутся своей короткой транзакцией** (`SqlClinicianSessions` получает
  `async_sessionmaker`): продление сеанса происходит при любом запросе панели, в том числе при
  чтении, где сценарий ничего не фиксирует (ADR-0005).
- **Текущий врач** — `CurrentClinician` из `features.access.api`, его отдаёт dishka по cookie;
  нет сеанса — `401 session_required`. Пациент для панели — только через
  `require_patient(registry, patient_id, clinician)`: чужой пациент — `404`, как несуществующий.
- **Журнал доступа** `access_records`: врач, действие, идентификатор объекта, момент — без ФИО и
  диагноза. Пишется в транзакции сценария; сейчас — открытие и правка плана реабилитации.
- **Администрирование** — команда `python -m kardiomonitor.app.admin` (создать врача, назначить
  лечащего врача, список пациентов без врача). Пароль вводится в скрытом приглашении, не в
  аргументах команды.
- Ключ панели (`KARDIO_DASHBOARD_KEY`, `X-Dashboard-Key`) удалён.

## Последствия

- Каждый эндпоинт панели получает врача; тест обходит все маршруты `/patients/{patient_id}…` и
  проверяет `404` для чужого врача.
- `SameSite=Strict` и JSON-тела закрывают CSRF для панели с того же адреса; отдельный CSRF-токен
  не нужен, пока панель и API на одном адресе.
- Пациенты, зарегистрированные с телефона по имени, не видны никому, пока администратор не
  назначит им врача (до QR v2, ТР-07).
- Новая зависимость `argon2-cffi` (C-расширение, колёса для Linux, macOS, Windows).

## Отвергнутые варианты

- `hashlib.scrypt` из стандартной библиотеки — без зависимости, но ТР-11 требует Argon2id
  (первый выбор OWASP).
- JWT вместо сеанса в базе — нельзя завершить сеанс на сервере («Выйти») без списка отзыва.
- Токен в `localStorage` и заголовке `Authorization` — доступен любому скрипту страницы (XSS).
- Сеанс в транзакции запроса — продление терялось бы на запросах только для чтения.
