# ADR-0007: SQLite и схема без миграций для демо-прототипа

- Статус: принято (решение человека, 2026-10-16; пересмотреть перед реальными пациентами)
- Дата: 2026-10-16

## Контекст

Нужен демонстрационный прототип: сервер на ноутбуке, доступ через ngrok, один–два пациента.
PostgreSQL из ADR-0002 требует отдельного процесса (docker) и настройки — лишнее для демо.

## Решение

- База — SQLite-файл (`KARDIO_DATABASE_URL=sqlite+aiosqlite:///./kardio.db`) через
  SQLAlchemy 2.0 async и `aiosqlite`. Код работает через SQLAlchemy: смена базы — смена
  адреса и диалекта upsert.
- Схема создаётся при запуске (`metadata.create_all` в `lifespan`), Alembic не используется.
  Изменили таблицы — удалить `kardio.db` (данные демо не ценны).
- Особенности SQLite учтены в коде:
  - время хранится в UTC без пояса (тип `UtcDateTime` в `platform/db/base.py` переводит
    туда и обратно; время без пояса записать нельзя);
  - внешние ключи включаются `PRAGMA foreign_keys=ON`, журнал — WAL;
  - upsert — `sqlite.insert(...).on_conflict_do_update`, порциями по 1000 строк (лимит
    параметров запроса).
- Тесты репозиториев — на настоящей SQLite во временном файле (`tests/database.py`).

## Последствия

- Запуск демо — одна команда, без docker.
- Запись последовательная (один писатель): для одного–двух телефонов достаточно.
- Перед работой с реальными пациентами — PostgreSQL и Alembic (ADR-0002, новым ADR):
  заменить диалект upsert в `data/`, добавить миграции, вернуть тесты `-m db` на PostgreSQL.

## Отвергнутые варианты

- PostgreSQL сразу — docker и настройка на машине демо, а выигрыша для 1–2 пациентов нет.
- Хранение в JSON-файлах — нет транзакций и upsert, пришлось бы писать их самим.
