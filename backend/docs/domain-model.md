# Модель предметной области

Единый язык (ubiquitous language) бэкенда. **Имена в коде берутся из этой таблицы.**
Если для нового понятия нет термина — сначала добавьте его сюда, потом пишите код.

Предметная область: наблюдение за пациентами в кардиореабилитации после инфаркта
миокарда по данным фитнес-браслета Mi Smart Band 6. Телефон пациента выгружает данные с
браслета (см. [android/docs/domain-model.md](../../android/docs/domain-model.md)) и
передаёт их на сервер; клиника смотрит их на сервере.

> Данные браслета — бытовые, не медицинские. Сервер показывает динамику и не ставит
> диагнозов. Ответы API и тексты для клиники не должны звучать как медицинское заключение.
>
> При этом это **данные о здоровье** — особая категория персональных данных. Правила
> обращения — в [coding-rules.md](coding-rules.md#13-логирование-и-персональные-данные).

**Общие термины с Android-приложением** (`ActivityMinute`, `HeartRate`, `StepCount`,
`Intensity`, `ActivityKind`, `DailySummary`, `BatteryLevel`, `BandAddress`) означают то же
самое и подчиняются тем же правилам. Меняете правило здесь — меняйте его и в Android
(и наоборот), с тестом на одинаковых данных с обеих сторон.

## Глоссарий

### Контекст «Мониторинг» (`features.monitoring`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Минута активности | `ActivityMinute` | Value Object | Запись браслета за одну минуту пациента: время начала, шаги, пульс (может отсутствовать), тип активности, интенсивность. Неизменяемая. Ключ — пациент + время начала минуты |
| Время начала минуты | `started_at` | `datetime` с часовым поясом | Начало минуты, секунды и микросекунды равны 0. Хранится в UTC. Время без часового пояса — ошибка (`DomainRuleViolation`) |
| Пульс | `HeartRate` | Value Object (уд/мин) | Допустимо 11–249. «Замера нет» — `None`, а не `HeartRate`. Телефон уже перевёл значения браслета 0 и 255 в отсутствие замера |
| Шаги | `StepCount` | Value Object | Неотрицательное целое |
| Тип активности | `ActivityKind` | `StrEnum` | `not_worn` (браслет снят), `charging`, `sleep`, `other`. Расшифровку кодов браслета делает телефон |
| Код типа браслета | `raw_kind_code` | `int` 0–255 | Исходный код браслета, сохраняется без интерпретации — для будущей расшифровки (коды 80, 1, 90… пока не известны) |
| Интенсивность | `Intensity` | Value Object | Сырое значение браслета 0–255, смысл не расшифрован — не интерпретировать |
| Пакет минут | `MinuteBatch` | Value Object | Минуты одного пациента из одного запроса телефона. Не пустой, не больше 10 080 минут (7 суток — окно первой синхронизации телефона), без повторов времени начала |
| История активности | `ActivityHistory` | Repository (`Protocol`) | Все принятые минуты всех пациентов. `save(patient_id, batch) -> SaveOutcome`, `minutes_of(patient_id, day)`, `last_minute_of(patient_id)` |
| Квитанция загрузки | `UploadReceipt` | Value Object | Ответ телефону: сколько минут принято, сколько из них новых, последняя принятая минута пациента |
| Последняя принятая минута | `last_minute_of` | метод `ActivityHistory` | Время начала самой поздней сохранённой минуты пациента или `None`. Телефон продолжает выгрузку со следующей минуты (слайс `upload_cursor`) |
| Итоги дня | `DailySummary` | Value Object (производный) | Для минут одного дня: сумма шагов, пульс ср/мин/макс (среднее округляется вниз), покрытие пульсом, минуты без браслета (`not_worn` и `charging`). `DailySummary.of(minutes)`. **Те же правила, что в Android** |
| День пациента | `day` | `date` | Календарный день **в часовом поясе пациента** (`Patient.time_zone`), а не сервера и не UTC |
| Покрытие пульсом | `heart_rate_coverage_percent` | свойство `DailySummary` | Доля записанных минут дня, в которых есть пульс, 0–100 % |

### Контекст «Пациенты» (`features.patients`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Пациент | `Patient` | Aggregate root | Человек под наблюдением. Идентичность — `PatientId`. Содержит часовой пояс, выданный браслет, зарегистрированный телефон |
| Идентификатор пациента | `PatientId` | `NewType` над `UUID` | Выдаётся сервером. Не связан с ФИО и номером карты |
| Код пациента в клинике | `ClinicPatientCode` | Value Object | Как клиника называет пациента (номер карты или псевдоним). Хранить ли его — открытый вопрос (ниже) |
| Часовой пояс пациента | `time_zone` | `ZoneInfo` | IANA-имя (`Asia/Novosibirsk`). Определяет границы «дня пациента» |
| Адрес браслета | `BandAddress` | Value Object | MAC `AA:BB:CC:DD:EE:FF`, верхний регистр. Тот же, что в Android |
| Выдача браслета | `Patient.assign_band(address)` | метод агрегата | У пациента не больше одного браслета одновременно; новый браслет заменяет прежний |
| Телефон пациента | `PatientPhone` | Entity (внутри `Patient`) | Телефон, с которого пациент загружает данные. Один действующий на пациента; регистрация нового отзывает прежний токен |
| Токен загрузки | `UploadToken` | Value Object | **Секрет** телефона для `Authorization: Bearer`. Создаётся `secrets.token_urlsafe(32)`, показывается один раз, в базе — только хеш. `__repr__` не раскрывает значение |
| Текущий пациент | `CurrentPatient` | Зависимость (`api.py`) | Пациент, которому принадлежит токен запроса. Нет токена или он отозван — 401 |
| Заряд браслета | `BatteryLevel` | Value Object | 0–100 %. Тот же, что в Android |
| Журнал заряда | `BatteryLog` | Repository (`Protocol`) | Заряд браслета пациента по времени измерения: `record(patient_id, measured_at, level)`; повтор того же времени не дублирует запись |

### Планируемые контексты

- **Доступ** (`features.access`): сотрудник клиники (`Clinician`), вход, роли. Термины и
  способ входа согласовать с человеком до кода.
- **Реабилитация** (`features.rehab`): целевая зона пульса, тренировка (занятие ЛФК),
  превышение зоны, пульс покоя. Термины согласовать с врачом-реабилитологом до кода.

## Агрегаты и инварианты

| Агрегат | Корень | Инварианты |
|---|---|---|
| Пациент | `Patient` | Часовой пояс — существующее IANA-имя. Не больше одного браслета и одного действующего телефона. Регистрация нового телефона отзывает прежний токен |
| История активности | — (коллекция `ActivityMinute` пациента) | Одна запись на (пациент, минута): повторная загрузка той же минуты перезаписывает её (телефон присылает данные повторно после сбоя). Принятие пакета идемпотентно |

## События предметной области

Пока синхронные: реакция — чтение репозитория при следующем запросе, без шины событий.

| Событие | Когда | Кто реагирует |
|---|---|---|
| Минуты приняты | `ActivityHistory.save` записал пакет | Итоги дня считаются из истории при запросе — отдельной реакции нет |
| Телефон зарегистрирован | `Patient.register_phone` | Прежний токен перестаёт приниматься |
| Браслет заменён | `Patient.assign_band` с новым адресом | История пациента сохраняется: она принадлежит пациенту, а не браслету |

 │  supporting              │                                         │  core                    │
 └──────────────────────────┘                                         └──────────────────────────┘
          ▲                                                                       ▲

## Открытые вопросы (решает человек, до кода — не додумывать)

1. **Персональные данные.** Хранит ли сервер ФИО и контакты пациента или только
   `ClinicPatientCode`, а сопоставление остаётся в клинике? По умолчанию — только код.
2. **Ключ авторизации браслета.** Сейчас ключ получает только телефон (QR
   `kardio;<MAC>;<ключ>`). Сервер ключ **не принимает и не хранит**, пока это не решено ADR.
3. **Как телефон получает токен загрузки.** QR при выдаче браслета, код из клиники или
   вход пациента — решить вместе с изменением Android-приложения.
4. **Вход сотрудников клиники** (контекст «Доступ»): пароли, OIDC, VPN клиники.
5. **Срок хранения данных** и удаление по запросу пациента.

## Как добавлять понятия

1. Новый термин → строка в глоссарии (термин, имя в коде, тип, правила).
2. Правило предметной области → `__post_init__`, фабрика или метод доменного типа + тест,
   названный на языке предметной области.
3. Поле API → схема Pydantic в слайсе и перевод в доменный тип (`to_domain()`) — не
   наоборот: домен не знает о схемах.
4. Общий с Android термин → проверьте, что имя и правила совпадают с
   [android/docs/domain-model.md](../../android/docs/domain-model.md).
