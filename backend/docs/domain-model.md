# Модель предметной области

Единый язык (ubiquitous language) бэкенда. **Имена в коде берутся из этой таблицы.**
Если для нового понятия нет термина — сначала добавьте его сюда, потом пишите код.

Предметная область: наблюдение за пациентами в кардиореабилитации после инфаркта
миокарда по данным фитнес-браслета Mi Smart Band 6. Телефон пациента выгружает данные с
браслета (см. [android/docs/domain-model.md](../../android/docs/domain-model.md)) и
передаёт их на сервер; клиника смотрит их на панели.

> Данные браслета — бытовые, не медицинские. Сервер показывает динамику и не ставит
> диагнозов. Ответы API и тексты панели не должны звучать как медицинское заключение.
>
> При этом это **данные о здоровье** — особая категория персональных данных. Правила
> обращения — в [coding-rules.md](coding-rules.md#13-логирование-и-персональные-данные).

**Общие термины с Android-приложением** (`ActivityMinute`, `HeartRate`, `StepCount`,
`Intensity`, `ActivityKind`, `DailySummary`, `PatientName`, `UploadToken`) означают то же самое
и подчиняются тем же правилам. Меняете правило здесь — меняйте его и в Android (и наоборот),
с тестом на одинаковых данных с обеих сторон (`test_daily_summary.py` ↔ `DailySummaryTest`).

## Глоссарий

### Контекст «Мониторинг» (`features.monitoring`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Минута активности | `ActivityMinute` | Value Object | Запись браслета за одну минуту пациента: время начала, шаги, пульс (может отсутствовать), тип активности, код браслета, интенсивность. Неизменяемая. Ключ — пациент + время начала |
| Время начала минуты | `started_at` | `datetime` с поясом | Секунды и микросекунды = 0 (`minute_not_aligned`). Хранится в UTC. Без пояса — `naive_datetime` |
| Пульс | `HeartRate` | Value Object (уд/мин) | 11–249 (`heart_rate_out_of_range`). «Замера нет» — `None`. Значения браслета 0 и 255 телефон уже перевёл в `None` |
| Шаги | `StepCount` | Value Object | Неотрицательное целое |
| Тип активности | `ActivityKind` | `StrEnum` | `not_worn` (снят), `charging`, `sleep`, `other`. Расшифровку кодов браслета делает телефон. `is_worn` — не `not_worn` и не `charging` |
| Код типа браслета | `kind_code` | `int \| None`, 0–255 | Исходный код браслета для `other` (80, 1, 90… не расшифрованы) — сохраняется для будущей расшифровки. Для остальных типов `None` |
| Интенсивность | `Intensity` | Value Object | Сырое значение браслета 0–255, смысл не расшифрован — не интерпретировать |
| Пакет минут | `MinuteBatch` | Value Object | Минуты одного запроса телефона: не пустой, ≤ 10 080 (7 суток — окно первой синхронизации телефона), без повторов `started_at` |
| История активности | `ActivityHistory` | Repository (`Protocol`) | Все принятые минуты. `save(patient_id, batch) -> SaveOutcome`, `last_minute_of(patient_id)`, `minutes_between(patient_id, start, end)` |
| Новые минуты | `SaveOutcome.new_minutes` | Value Object | Сколько минут пакета раньше не было в истории |
| Квитанция загрузки | `UploadReceipt` | Value Object (слайс `minute_upload`) | Сколько принято, сколько новых, последняя минута пациента |
| Последняя принятая минута | `last_minute_of` | метод `ActivityHistory` | Самая поздняя минута пациента или `None`. Телефон продолжает со следующей (слайс `upload_cursor`) |
| Итоги дня | `DailySummary` | Value Object (производный) | Для минут одного дня: сумма шагов, пульс ср/мин/макс (среднее округляется вниз), покрытие пульсом, минуты без браслета. `DailySummary.of(minutes)`. **Те же правила, что в Android** |
| Покрытие пульсом | `heart_rate_coverage_percent` | свойство `DailySummary` | Доля минут дня с пульсом, 0–100 % (округление вниз) |
| День пациента | `PatientDay` | Value Object | Календарный день **в часовом поясе пациента**: `start` — его полночь, `end` — следующая. Минута 23:59 по Новосибирску — в своём дне, а не в следующем по UTC |
| Пульс сейчас | `LiveHeartRateReading` | Value Object | Значение непрерывного измерения (`HeartRate`) и момент замера (с поясом). Телефон шлёт раз в 2–3 с, пока пациент держит измерение включённым |
| Журнал пульса сейчас | `LiveHeartRateLog` | Repository (`Protocol`) | `record`, `readings_since(patient_id, since)`, `latest_of(patient_id)`. Повтор того же момента не дублирует |

### Контекст «Пациенты» (`features.patients`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Пациент | `Patient` | Aggregate root | Человек под наблюдением: `PatientId`, имя, часовой пояс, момент регистрации. Создаётся `Patient.register(name, time_zone, now=…)` |
| Идентификатор пациента | `PatientId` | `NewType` над `UUID` | Выдаётся сервером, не связан с ФИО и номером карты |
| Имя пациента | `PatientName` | Value Object | Как показать пациента на панели: 1–100 знаков, без пробелов по краям (`invalid_patient_name`). Вводится в приложении |
| Часовой пояс пациента | `time_zone` | `ZoneInfo` | IANA-имя часового пояса телефона при регистрации (`unknown_time_zone`). Определяет «день пациента» |
| Регистрация | `register_patient` | Сценарий (слайс `registration`) | Новый пациент + новый токен загрузки; итог — `PatientRegistration` |
| Токен загрузки | `UploadToken` | Value Object | **Секрет** телефона для `Authorization: Bearer`. `secrets.token_urlsafe(32)`, показывается один раз, в базе — только `fingerprint` (SHA-256). `repr` не раскрывает значение |
| Реестр пациентов | `PatientRegistry` | Repository (`Protocol`) | `add(patient, token)`, `by_token`, `by_id`, `all_patients` |
| Текущий пациент | `CurrentPatient` | `NewType` над `Patient` (`api.py`) | Владелец токена запроса; отдаёт dishka. Нет токена или он неизвестен — `401` |

### Планируемые контексты

- **Доступ** (`features.access`): сотрудник клиники (`Clinician`), вход, роли. Пока панель
  защищена общим ключом (`KARDIO_DASHBOARD_KEY`). Термины согласовать с человеком до кода.
- **Реабилитация** (`features.rehab`): целевая зона пульса, тренировка (занятие ЛФК),
  превышение зоны, пульс покоя. Термины согласовать с врачом-реабилитологом до кода.
- **Браслет пациента и заряд** (`patients`, слайс `battery_report`): `BandAddress`,
  `BatteryLevel`, журнал заряда — когда понадобится.

## Агрегаты и инварианты

| Агрегат | Корень | Инварианты |
|---|---|---|
| Пациент | `Patient` | Имя и часовой пояс валидны. Один токен загрузки на пациента (регистрация с телефона = новый пациент) |
| История активности | — (коллекция `ActivityMinute` пациента) | Одна запись на (пациент, минута): повтор перезаписывает. Приём пакета идемпотентен и атомарен |

## События предметной области

Синхронные: реакция — чтение репозитория при следующем запросе, без шины событий.

| Событие | Когда | Кто реагирует |
|---|---|---|
| Минуты приняты | `ActivityHistory.save` + фиксация | Панель видит их при следующем опросе дня (раз в 15 с) |
| Пульс сейчас принят | `LiveHeartRateLog.record` + фиксация | Панель видит значение при следующем опросе (раз в 2 с) |

## Открытые вопросы (решает человек, до кода — не додумывать)

1. ~~Хранить ли имя пациента~~ — **для демо решено**: имя, которое вводит пациент. Для
   реальных пациентов — пересмотреть (код клиники вместо имени, сопоставление вне системы).
2. **Ключ авторизации браслета.** Сервер ключ **не принимает и не хранит**, пока это не решено ADR.
3. ~~Как телефон получает токен~~ — **для демо решено**: регистрация по имени с телефона.
   Для реальных пациентов — регистрация клиникой и QR (чтобы посторонний не мог создать пациента).
4. **Вход сотрудников клиники** (контекст «Доступ»): пароли, OIDC, VPN клиники.
5. **Срок хранения данных** и удаление по запросу пациента.

## Как добавлять понятия

1. Новый термин → строка в глоссарии (термин, имя в коде, тип, правила).
2. Правило предметной области → `__post_init__`, фабрика или метод доменного типа + тест,
   названный на языке предметной области.
3. Поле API → схема Pydantic в слайсе и перевод в доменный тип (`to_domain()`) — домен о
   схемах не знает.
4. Общий с Android термин → проверьте, что имя и правила совпадают с
   [android/docs/domain-model.md](../../android/docs/domain-model.md).
