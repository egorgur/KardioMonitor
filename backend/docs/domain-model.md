# Модель предметной области

Единый язык (ubiquitous language) бэкенда. **Имена в коде берутся из этой таблицы.**
Если для нового понятия нет термина — сначала добавьте его сюда, потом пишите код.

Предметная область: наблюдение за пациентами в кардиореабилитации после инфаркта
миокарда по данным фитнес-браслета Mi Smart Band 6. Телефон пациента выгружает данные с
браслета (см. [android/docs/domain-model.md](../../android/docs/domain-model.md)) и
передаёт их на сервер; клиника смотрит их на панели.

> Данные браслета — бытовые, не медицинские. Сервер показывает динамику и не ставит
> диагнозов. Ответы API и тексты панели не должны звучать как медицинское заключение.
>
> При этом это **данные о здоровье** — особая категория персональных данных. Правила
> обращения — в [coding-rules.md](coding-rules.md#13-логирование-и-персональные-данные).

**Общие термины с Android-приложением** (`ActivityMinute`, `HeartRate`, `StepCount`,
`Intensity`, `ActivityKind`, `DailySummary`, `PatientName`, `UploadToken`) означают то же самое
и подчиняются тем же правилам. Меняете правило здесь — меняйте его и в Android (и наоборот),
с тестом на одинаковых данных с обеих сторон (`test_daily_summary.py` ↔ `DailySummaryTest`).

## Глоссарий

### Контекст «Мониторинг» (`features.monitoring`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Минута активности | `ActivityMinute` | Value Object | Запись браслета за одну минуту пациента: время начала, шаги, пульс (может отсутствовать), тип активности, код браслета, интенсивность. Неизменяемая. Ключ — пациент + время начала |
| Время начала минуты | `started_at` | `datetime` с поясом | Секунды и микросекунды = 0 (`minute_not_aligned`). Хранится в UTC. Без пояса — `naive_datetime` |
| Пульс | `HeartRate` | Value Object (уд/мин) | 11–249 (`heart_rate_out_of_range`). «Замера нет» — `None`. Значения браслета 0 и 255 телефон уже перевёл в `None` |
| Шаги | `StepCount` | Value Object | Неотрицательное целое |
| Тип активности | `ActivityKind` | `StrEnum` | `not_worn` (снят), `charging`, `sleep`, `other`. Расшифровку кодов браслета делает телефон. `is_worn` — не `not_worn` и не `charging` |
| Код типа браслета | `kind_code` | `int \| None`, 0–255 | Исходный код браслета для `other` (80, 1, 90… не расшифрованы) — сохраняется для будущей расшифровки. Для остальных типов `None` |
| Интенсивность | `Intensity` | Value Object | Сырое значение браслета 0–255, смысл не расшифрован — не интерпретировать |
| Пакет минут | `MinuteBatch` | Value Object | Минуты одного запроса телефона: не пустой, ≤ 10 080 (7 суток — окно первой синхронизации телефона), без повторов `started_at` |
| История активности | `ActivityHistory` | Repository (`Protocol`) | Все принятые минуты. `save(patient_id, batch) -> SaveOutcome`, `last_minute_of(patient_id)`, `minutes_between(patient_id, start, end)` |
| Новые минуты | `SaveOutcome.new_minutes` | Value Object | Сколько минут пакета раньше не было в истории |
| Квитанция загрузки | `UploadReceipt` | Value Object (слайс `minute_upload`) | Сколько принято, сколько новых, последняя минута пациента |
| Последняя принятая минута | `last_minute_of` | метод `ActivityHistory` | Самая поздняя минута пациента или `None`. Телефон продолжает со следующей (слайс `upload_cursor`) |
| Итоги дня | `DailySummary` | Value Object (производный) | Для минут одного дня: сумма шагов, пульс ср/мин/макс (среднее округляется вниз), покрытие пульсом, минуты без браслета. `DailySummary.of(minutes)`. **Те же правила, что в Android** |
| Покрытие пульсом | `heart_rate_coverage_percent` | свойство `DailySummary` | Доля минут дня с пульсом, 0–100 % (округление вниз) |
| Распределение пульса | `HeartRateDistribution` | Value Object (производный) | Сколько минут пульс был в каждом интервале: `< 40`, `40–49`, …, `110–119`, `120+` (левая граница включительно, шаг 10 уд/мин). Учитываются только минуты с пульсом: сумма по интервалам = число минут с пульсом. `HeartRateDistribution.of(minutes)`. ТР-04 |
| Интервал пульса | `HeartRateBand` | Value Object | `from_bpm` (None — «ниже 40») и `to_bpm` включительно (None — «120 и выше») и число минут |
| День пациента | `PatientDay` | Value Object | Календарный день **в часовом поясе пациента**: `start` — его полночь, `end` — следующая. Минута 23:59 по Новосибирску — в своём дне, а не в следующем по UTC |
| Пульс сейчас | `LiveHeartRateReading` | Value Object | Значение непрерывного измерения (`HeartRate`) и момент замера (с поясом). Телефон шлёт раз в 2–3 с, пока пациент держит измерение включённым |
| Журнал пульса сейчас | `LiveHeartRateLog` | Repository (`Protocol`) | `record`, `readings_since(patient_id, since)`, `latest_of(patient_id)`. Повтор того же момента не дублирует |
| Запрос пульса в прямом режиме | `LiveHeartRateRequest` | Aggregate root | Команда врача одному пациенту: длительность 1–60 мин (по умолчанию 10), создана сейчас, ожидает телефон не больше 2 ч. Переходы: `waiting_for_phone` → `running` → `completed`/`stopped_by_patient`/`failed`; из ожидания допустим `failed`. Повтор текущего состояния идемпотентен |
| Состояние запроса пульса | `LiveHeartRateRequestStatus` | `StrEnum` | `waiting_for_phone`, `running`, `completed`, `stopped_by_patient`, `failed`. Терминальное состояние не меняется |
| Причина невыполнения запроса | `LiveHeartRateFailureReason` | `StrEnum` | `expired`, `band_unavailable`, `notification_permission_denied`, `companion_association_missing`, `measurement_failed`; заполнена только для `failed` |
| Запросы пульса | `LiveHeartRateRequests` | Repository (`Protocol`) | Создать, получить последний и активный запрос пациента, сохранить переход. Одновременно один нетерминальный запрос; просроченное ожидание становится `failed` / `expired` |
| Минуты приняты | `MinutesReceived` | Событие | Пакет минут пациента сохранён в истории (до фиксации): пациент и минуты пакета (ADR-0009) |
| Пульс сейчас принят | `LiveHeartRateReceived` | Событие | Значение «пульса сейчас» сохранено (до фиксации): пациент и замер |
| Подписчик Мониторинга | `MonitoringSubscriber` | Порт (`Protocol`) | Реакция верхних контекстов на принятые данные, в транзакции приёма: `minutes_received`, `live_heart_rate_received`. Несколько — `MonitoringSubscribers`; связывает `app` |

### Контекст «Пациенты» (`features.patients`)

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Пациент | `Patient` | Aggregate root | Человек под наблюдением: `PatientId`, имя, часовой пояс, момент регистрации, лечащий врач. Создаётся `Patient.register(name, time_zone, now=…)` |
| Лечащий врач | `attending_clinician_id` | `ClinicianId \| None` | Единственный врач, который видит пациента на панели (ТР-11). None — не назначен (регистрация с телефона по имени): пациента видит только администратор сервера. Назначает администратор: `with_attending_clinician`; `is_attended_by(clinician_id)` |
| Идентификатор пациента | `PatientId` | `NewType` над `UUID` | Выдаётся сервером, не связан с ФИО и номером карты |
| Имя пациента | `PatientName` | Value Object | Как показать пациента на панели: 1–100 знаков, без пробелов по краям (`invalid_patient_name`). Вводится в приложении или — у пациента от клиники — это ФИО. `matches(query)` — поиск ТР-06: подстрока без учёта регистра и `ё`/`е` |
| Часовой пояс пациента | `time_zone` | `ZoneInfo` | IANA-имя часового пояса телефона при регистрации (`unknown_time_zone`). Определяет «день пациента»; `Patient.day_of(moment)` — день пациента, в который попадает момент |
| Регистрация | `register_patient` | Сценарий (слайс `registration`) | Новый пациент + новый токен загрузки; итог — `PatientRegistration` |
| Создание пациента клиникой | `Patient.admit`, `admit_patient` | Фабрика, сценарий (слайс `admission`) | Врач вводит карточку; имя — ФИО; врач становится лечащим; дата рождения — не в будущем, возраст 18–120 (`invalid_birth_date`). Программа — по умолчанию (ТР-07, [ADR-0012](adr/0012-clinic-admission-enrollment-code.md)) |
| Карточка пациента | `PatientProfile` | Value Object | `FullName` (фамилия, имя — обязательно, отчество; части 1–32 знака, `invalid_full_name`), дата рождения, `BodyParameters` (рост 100–250 см, вес 30–300 кг, диагноз 1–1000 знаков — `invalid_body_parameters`). `age_on(day)`. **Особая категория ПДн**: только лечащему врачу, не в журналы, `repr` скрывает |
| Код привязки | `EnrollmentCode` | Value Object | Одноразовый **секрет** для QR v2 (`e=`): 128 бит, base64url, действует 72 ч; в базе — отпечаток. Новый код отменяет прежние |
| Коды привязки | `EnrollmentCodes` | Repository (`Protocol`) | `issue(patient_id, code, expires_at)`, `redeem(code, now) -> PatientId \| None` — атомарно, один раз |
| Привязка телефона | `enroll_phone` | Сценарий (слайс `enrollment`) | Код → новый токен загрузки пациента; прежний токен перестаёт действовать (`invalid_enrollment_code`) |
| Токен загрузки | `UploadToken` | Value Object | **Секрет** телефона для `Authorization: Bearer`. `secrets.token_urlsafe(32)`, показывается один раз, в базе — только `fingerprint` (SHA-256). `repr` не раскрывает значение |
| Реестр пациентов | `PatientRegistry` | Repository (`Protocol`) | `add(patient, token)`, `by_token`, `by_id`, `all_patients`, `patients_of(clinician_id)`, `save_attending_clinician(patient)`, `admit(patient, profile)`, `profile_of(patient_id)`, `replace_token(patient_id, token)` |
| Текущий пациент | `CurrentPatient` | `NewType` над `Patient` (`api.py`) | Владелец токена запроса; отдаёт dishka. Нет токена или он неизвестен — `401` |
| Пациенты врача | `AttendedPatients` | Опубликованный API (`api.py`) | Пациенты вошедшего врача: `require(patient_id, recording=…)` — свой пациент или `404` (чужой отвечает как несуществующий) и запись в журнал доступа; `all(search=…)`; `record(action, patient_id)`. Существует только при сеансе врача. Единственный путь к пациенту для эндпоинтов панели |

### Контекст «Доступ» (`features.access`)

ТР-11 в [docs/requirements.md](../../docs/requirements.md), [ADR-0011](adr/0011-clinician-sign-in-argon2-sessions.md).
«Доступ» — нижний контекст: пациентов не знает (ADR-0008).

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Врач | `Clinician` | Aggregate root | Сотрудник клиники с аккаунтом на панели: `ClinicianId`, логин, имя, хеш пароля, счётчик неудачных входов, блокировка. Видит только своих пациентов. Создаёт администратор (`app/admin.py`) |
| Идентификатор врача | `ClinicianId` | `NewType` над `UUID` | Выдаётся сервером |
| Логин | `Login` | Value Object | 3–32 знака: строчные латинские буквы, цифры, `.`, `_`, `-` (`invalid_login`). При входе — без учёта регистра и пробелов по краям |
| Имя врача | `ClinicianName` | Value Object | Для шапки панели: 1–100 знаков (`invalid_clinician_name`) |

| Токен сеанса | `SessionToken` | Value Object | **Секрет** в cookie `kardio_session`: 256 бит, в базе — только `fingerprint` (SHA-256) |
| Сеанс врача | `ClinicianSession` | Value Object | Врач, начало, последний запрос. Истекает через 8 ч без запросов; последний запрос записывается не чаще раза в 5 мин |
| Сеансы врачей | `ClinicianSessions` | Repository (`Protocol`) | `start`, `by_token`, `touch`, `end`. Пишутся своей транзакцией (ADR-0011) |
| Текущий врач | `CurrentClinician` | `NewType` над `Clinician` (`api.py`) | Владелец сеанса запроса; отдаёт dishka. Нет сеанса или он истёк — `401 session_required` |
| Журнал доступа | `AccessLog`, `AccessAction` | Repository (`Protocol`), `StrEnum` | Кто, что, к какому объекту (идентификатор), когда — без ФИО и диагноза (ТР-11, п. 6). Сейчас: `created_patient`, `viewed_patient_card`, `issued_enrollment_code`, `viewed_rehab_plan`, `changed_rehab_plan` |

### Контекст «Реабилитация» (`features.rehab`)

Нормы и программа врача и правила их выполнения — ТР-01…ТР-03, ТР-05 в
[docs/requirements.md](../../docs/requirements.md). Решения — [ADR-0008](adr/0008-rehab-alerts-access-contexts.md),
[ADR-0010](adr/0010-rehab-plan-revisions.md). Каждое значение по умолчанию и каждый предел — одна
константа в домене контекста.

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Зона тренировочного пульса | `TrainingHeartRateZone` | Value Object | `[lower_bpm, upper_bpm]`, границы включительно; `40 ≤ нижняя < верхняя ≤ 220` (`invalid_training_zone`). `contains(heart_rate)` |
| Нормы дня | `DailyTargets` | Value Object | Зона, тренировочных минут в день (1–1440), шагов в день (0–100 000) (`invalid_daily_targets`). По умолчанию 90–110 уд/мин, 30 мин, 10 000 шагов |
| День программы | `ProgramDay` | `NewType` над `int` | Номер дня от начала программы: начало — день 1. Дни — по часовому поясу пациента |
| Этап программы | `RehabStage` | Value Object | Дни `first_day`–`last_day` (включительно, `1 ≤ first ≤ last`) и нормы дня (`invalid_rehab_stage`) |
| Программа реабилитации | `RehabProgram` | Value Object | Дата начала (день 1), длительность 1–365 дней (`invalid_program_duration`), этапы подряд без пропусков и пересечений от дня 1 до последнего (`invalid_program_stages`: «дни 16–17 не входят ни в один этап»). По умолчанию — 42 дня одним этапом с нормами по умолчанию |
| Параметры наблюдения | `MonitoringSettings` | Value Object | Порог ходьбы (шагов в минуту, 1–250, по умолчанию 60), порог высокого пульса (60–250 уд/мин), порог «почти не ходит» (шагов в день, 0–100 000), время дневных оповещений (UTC), независимый верхний порог тренировочных минут `training_minutes_upper_threshold` (целое 1–1440 или `null`, по умолчанию выключен) (`invalid_monitoring_settings`). Значения по умолчанию порогов и времени — пример до ответа клиники (В-21) |
| Версия программы | `ProgramRevision` | Value Object | День начала действия, программа и параметры наблюдения. Действует до начала следующей версии |
| План реабилитации | `RehabPlan` | Aggregate root | Версии программы пациента по возрастанию дня начала (хотя бы одна). `default_for(patient)` — программа по умолчанию с дня регистрации, в базу не пишется. `revised(program, settings, today)` — новая версия с сегодняшнего дня (вторая правка за день заменяет версию дня). `targets_on(day)` — нормы по версии, действовавшей в день; дня нет в программе своей версии — по текущей |
| Планы реабилитации | `RehabPlans` | Repository (`Protocol`) | `of(patient_id) -> RehabPlan \| None` (None — план не сохранялся), `save(plan)` |
| Минута ходьбы | `walking_minute_class` | правило | Браслет надет и шагов за минуту **больше** порога ходьбы (ровно порог — не ходьба). Не ходьба — `None` |
| Вид минуты ходьбы | `WalkingMinuteClass` | `StrEnum` | `training` (пульс в зоне — **тренировочная минута**), `above_zone`, `below_zone`, `no_heart_rate`. **Те же правила, что в Android** (этап 4) |
| Выполнение нормы за день | `DailyTargetProgress` | Value Object (производный) | Нормы дня, тренировочных минут, шагов за день (все шаги), минут ходьбы и минут ходьбы без пульса; `is_final` — сутки закончились; `is_met` — данные есть, минут ≥ нормы **и** шагов ≥ нормы. **Те же правила, что в Android** |
| Состояние дня программы | `ProgramDayStatus` | `StrEnum` | `met`, `not_met`, `no_data` (минут нет — норма не выполнена), `in_progress` (сегодня) |
| Прогресс реабилитации | `RehabProgress` | Value Object (производный) | «День X из Y», в скольких завершённых днях норма выполнена, текущий этап, состояние каждого прошедшего дня, выполнение нормы сегодня (`today`); `period(plan, …)` — какие минуты нужны; `from_outcomes` — по готовым итогам дней (кеш); программа завершена — после последнего дня. Сегодня в «прошло», но не в счёт выполненных |
| Итоги дня (кеш) | `DayOutcomes` | Repository (`Protocol`) | Выполнение нормы каждого прошедшего дня программы, посчитанное по всем минутам дня, — для списка пациентов (ТР-06, п. 4). Пересчитывается подписчиком `MinutesReceived` (слайс `day_outcome_refresh`), недостающие дни — при чтении; сохранение плана сбрасывает итоги пациента. Источник истины — минуты |

### Контекст «Оповещения» (`features.alerts`)

ТР-08 в [docs/requirements.md](../../docs/requirements.md); решения — [ADR-0008](adr/0008-rehab-alerts-access-contexts.md),
[ADR-0009](adr/0009-reactions-and-periodic-checks.md). Пороги и время проверок — из параметров
наблюдения (`MonitoringSettings`) версии плана, действовавшей в день события.

| Термин | Имя в коде | Тип | Определение и правила |
|---|---|---|---|
| Оповещение | `PatientAlert` | Entity | Запись о событии у пациента: вид, день (у дневных) или эпизод, значения, момент создания, когда врач отметил «просмотрено». Видят врач и пациент. Не удаляется. **Не путать с напоминанием** (ТР-10, только телефон). Текстов не хранит — только значения (тексты утверждает врач, В-19) |
| Вид оповещения | `AlertKind` | `StrEnum` | `high_heart_rate`, `daily_target_missed`, `daily_target_met`, `low_activity`, `training_minutes_exceeded`. `is_daily` — имеет день; `is_scheduled` — только три прежних плановых вида |
| Замер пульса | `HeartRatePoint` | Value Object | Момент и пульс: минута активности (момент — её начало) или «пульс сейчас» |
| Превышение тренировочных минут | `TrainingMinutesExceeded` | Value Object | Неизменяемый снимок `{training_minutes, threshold_minutes}` первого строгого превышения по полному дню пациента; только программа своей версии, исторические зона и порог ходьбы. Проверка после любого upload (включая исправления), при правке плана — сегодня. Не live и не планировщик; рост и исправления не меняют снимок, просмотр и курсор |
| Эпизод высокого пульса | `HighHeartRateEpisode` | Value Object | Замеры выше порога, между которыми перерыв не больше 5 минут (В-15), при любой активности: начало, последний замер, максимум, порог. Длительность — от начала первой до конца последней минуты (10:01–10:06 — 6 мин). Пульс ровно на пороге — не высокий |
| Оповещение на эпизод | `alert_for_episode` | правило | Новый эпизод — новое оповещение; уже записанный — ничего (повтор тех же минут, п. 6); продолжение записанного — то же оповещение с продлённым эпизодом, снова непросмотренное |
| Дневная проверка | `DailyCheck` | Value Object | Наступает в `daily_alert_time_utc` текущего дня UTC; оценивает день пациента (в его поясе), в который попадает этот момент, по минутам с начала дня до момента проверки. Всегда «норма выполнена» или «не выполнена» и, если шагов меньше порога, «почти не ходит». Одна на день пациента; поздние минуты её не повторяют (В-16). Нет — до времени, для дней вне программы (В-01) и если момент раньше регистрации пациента |
| Журнал оповещений | `AlertJournal` | Repository (`Protocol`) | Уникальность — в базе: (пациент, вид, день) и (пациент, вид, начало эпизода). Лента телефона — по позиции `FeedEntry.position`, растущей с каждой записью (новой или изменённой) |
| Непросмотренные | `unviewed_counts` | метод `AlertJournal` | Оповещения пациента без отметки врача — число в списке пациентов (ТР-06) |

### Планируемые контексты

- **Браслет пациента и заряд** (`patients`, слайс `battery_report`): `BandAddress`,
  `BatteryLevel`, журнал заряда — когда понадобится.

## Агрегаты и инварианты

| Агрегат | Корень | Инварианты |
|---|---|---|
| Пациент | `Patient` | Имя и часовой пояс валидны. Один токен загрузки на пациента (регистрация с телефона = новый пациент). Не больше одного лечащего врача |
| Врач | `Clinician` | Логин уникален. Пароль — только хешем. Блокировка после 5 неудач подряд |
| План реабилитации | `RehabPlan` | Хотя бы одна версия; дни начала версий различны и по возрастанию; программа версии валидна. Правка не меняет версий раньше сегодняшнего дня (ADR-0010) |
| История активности | — (коллекция `ActivityMinute` пациента) | Одна запись на (пациент, минута): повтор перезаписывает. Приём пакета идемпотентен и атомарен |
| Оповещение | `PatientAlert` | Значения — своего вида; день — только у дневного. Одно дневное на (пациент, вид, день), одно «высокий пульс» на эпизод. Не удаляется; «просмотрено» ставится один раз |

## События предметной области

Синхронные, без шины событий: панель видит изменения при следующем запросе.

| Событие | Когда | Кто реагирует |
|---|---|---|
| Минуты приняты | `ActivityHistory.save` + фиксация | Панель видит их при следующем опросе дня (раз в 15 с) |
| Пульс сейчас принят | `LiveHeartRateLog.record` + фиксация | Панель видит значение при следующем опросе (раз в 2 с) |

Реакция верхних контекстов — синхронно, через порт `MonitoringSubscriber`, в транзакции приёма
(ADR-0009): `MinutesReceived` — «высокий пульс» (Оповещения) и пересчёт итогов дня (Реабилитация);
`LiveHeartRateReceived` — «высокий пульс». Дневные оповещения — периодическая задача раз в минуту.

## Открытые вопросы (решает человек, до кода — не додумывать)

1. ~~Хранить ли имя пациента~~ — **для демо решено**: имя, которое вводит пациент. **Для
   реальных пациентов решено 2026-10-29 и сделано:** ФИО, дата рождения и биопараметры (рост, вес,
   диагноз) вводит клиника, хранятся в базе сервера — ТР-07,
   [ADR-0012](adr/0012-clinic-admission-enrollment-code.md).
2. **Ключ авторизации браслета.** Сервер ключ **не принимает и не хранит**, пока это не решено ADR.
3. ~~Как телефон получает токен~~ — **для демо решено**: регистрация по имени с телефона.
   Для реальных пациентов — **сделано на сервере**: пациента создаёт врач, телефон привязывается
   одноразовым кодом из QR v2 (`POST /api/v1/enroll`, ADR-0012); телефон и утилита — ещё нет.
4. ~~Вход сотрудников клиники~~ — **решено 2026-10-29 и сделано:** аккаунт врача, врач видит своих
   пациентов (ТР-11, ADR-0011). Логин и пароль, администратор — команда на сервере, сеанс 8 ч, других
   ролей нет — решено 2026-10-29 (В-23 в `docs/requirements.md`).
5. **Срок хранения данных** и удаление по запросу пациента.
6. **Выдачи браслетов.** Браслет после возврата выдаётся следующему пациенту с тем же ключом
   ([android ADR-0011](../../android/docs/adr/0011-band-reissue-keeps-key.md), П2). Хранить ли на
   сервере «браслет → пациент, выдан, возвращён» и отклонять минуты после возврата — решается
   вместе с регистрацией клиникой (вопрос 3), до кода — контракт API и ADR.

## Как добавлять понятия

1. Новый термин → строка в глоссарии (термин, имя в коде, тип, правила).
2. Правило предметной области → `__post_init__`, фабрика или метод доменного типа + тест,
   названный на языке предметной области.
3. Поле API → схема Pydantic в слайсе и перевод в доменный тип (`to_domain()`) — домен о
   схемах не знает.
4. Общий с Android термин → проверьте, что имя и правила совпадают с
   [android/docs/domain-model.md](../../android/docs/domain-model.md).
