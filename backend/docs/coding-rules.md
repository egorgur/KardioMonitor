# Правила написания кода

Цель — код, который ИИ-агент и человек могут **найти, понять и безопасно изменить**,
прочитав минимум файлов. Каждое правило сопровождается причиной: если правило мешает
в конкретном случае, причина подскажет, можно ли отступить.

Структура и границы — в [architecture.md](architecture.md), термины — в
[domain-model.md](domain-model.md), тесты — в [testing.md](testing.md), HTTP-контракт —
в [api-contract.md](api-contract.md).

Пометки: **[ruff]**, **[mypy]**, **[import-linter]** — правило проверяет инструмент;
**[тест]** — проверяет `tests/architecture/`. Нарушение роняет полную проверку.

## 1. Находимость

| Правило | Почему |
|---|---|
| Имя модуля = главное понятие или действие: `upload_minutes.py`, `activity_minute.py`, `router.py` слайса | Агент ищет по имени файла раньше, чем по содержимому |
| Один главный публичный тип или функция на модуль; мелкие `_private`-помощники — рядом | Модуль = единица смысла |
| Путь отражает контекст и слайс: `features/monitoring/minute_upload/` | Путь сам отвечает «к чему это относится» |
| Уникальные имена для разных понятий: не два класса `Item` или `Response` в разных пакетах | Поиск по имени возвращает одно место; меньше ошибочных импортов |
| **[тест]** Нет модулей `utils.py`, `helpers.py`, `common.py`, `services.py`, `misc.py` | В них стекается несвязанный код, и найти его по имени нельзя |

## 2. Имена

- **Из глоссария.** `ActivityMinute`, `HeartRate`, `DailySummary` — см. [domain-model.md](domain-model.md).
  Нет термина — добавьте его в глоссарий в той же задаче.
- **PEP 8 [ruff `N`]:** модули и функции — `snake_case`, классы — `PascalCase`,
  константы — `UPPER_SNAKE_CASE`, приватное — с `_`.
- **[тест] Запрещены пустые суффиксы классов** в `features/`: `Manager`, `Helper`,
  `Util(s)`, `Processor`, `Handler`, `Service`, `Data`, `Info`, `Item`. Вместо
  `MinuteService` — сценарий `upload_minutes`, вместо `PatientManager` — `PatientRegistry`.
- **Сценарии — глаголом:** `upload_minutes`, `enroll_patient`, `summarize_day`.
- **Эндпоинты — по действию с точки зрения клиента:** `receive_activity_minutes`,
  `get_daily_summary`. Имя функции становится `operationId` в OpenAPI — не меняйте его без нужды.
- **Схемы API — с суффиксом направления:** `MinuteBatchIn`, `UploadReceiptOut`. Сразу
  видно, что это контракт, а не доменный тип.
- **Булевы — с `is_/has_/can_/should_`:** `is_revoked`, `has_heart_rate`.
- **Без сокращений**, кроме общепринятых (`id`, `db`, `api`, `utc`, `bpm`):
  `heart_rate`, не `hr`; `minutes`, не `mins`.
- **Единицы — в типе или имени:** `HeartRate` (уд/мин), `timeout_seconds`, `level_percent`.
- Идентификаторы — на английском; **комментарии, docstring, сообщения ошибок и
  `detail` в ответах API — на русском**.

## 3. Размеры

| Что | Ориентир | Проверка | Что делать, если больше |
|---|---|---|---|
| Модуль | ≤ 300 строк | **[тест]** | Разделить по смыслу: схемы / сценарий / эндпоинт |
| Функция | ≤ 40 строк, ≤ 30 операторов | **[ruff `PLR0915`]** | Выделить шаги с говорящими именами |
| Сложность функции | ≤ 10 | **[ruff `C901`]** | Ранний `return`, словарь вместо цепочки `if` |
| Параметров функции | ≤ 6 | **[ruff `PLR0913`]** | Сгруппировать в dataclass; в эндпоинте — в схему |
| Вложенность | ≤ 3 уровня | **[ruff `PLR1702`]** (preview-правило: включить `preview = true` или проверять ревью) | Ранний `return`, выделение функций |

Почему: агент читает модуль целиком; длинный модуль съедает контекст и прячет важное.

## 4. Типы вместо примитивов

```python
# Плохо: что это за int? Какой диапазон? Можно перепутать аргументы
async def save(patient: str, ts: datetime, hr: int | None, steps: int, kind: int) -> None: ...

# Хорошо: невалидное значение не создать, перепутать аргументы нельзя
@dataclass(frozen=True, slots=True)
class HeartRate:
    bpm: int

    def __post_init__(self) -> None:
        if not 11 <= self.bpm <= 249:
            raise DomainRuleViolation(f"пульс вне диапазона: {self.bpm}")

async def save(self, patient_id: PatientId, batch: MinuteBatch) -> SaveOutcome: ...
```

- Значение с правилами → `@dataclass(frozen=True, slots=True)` с проверкой в
  `__post_init__` или фабрикой `@classmethod`.
- Идентификатор без правил → `NewType("PatientId", UUID)`.
- Закрытый набор вариантов → `StrEnum` / `Enum`, а не строки и int-коды.
- Исходы сценария → объединение типов: `UploadAccepted | PatientNotFound`, разбор через `match`.
- В домене нет `dict[str, Any]`, `tuple` с позиционным смыслом и «голых» `str` для понятий.
- Коллекции в доменных типах — `tuple[...]` или `frozenset`, не `list`: объект неизменяем.
- Секреты (`UploadToken`) — `field(repr=False)` или свой `__repr__`, в настройках —
  `pydantic.SecretStr`: значение не попадает в лог и трассировку.

## 5. Явность и типизация

- **[mypy strict]** Все функции аннотированы, включая возврат. `Any` — только на
  границе с нетипизированной библиотекой, с комментарием почему (**[ruff `ANN401`]**).
- `# type: ignore` — только с кодом ошибки и причиной: `# type: ignore[arg-type]  # почему`.
- **[ruff `FBT`]** Булевы аргументы — только именованные: `def revoke(*, notify: bool)`.
  Зависимости сценария — тоже именованные после `*`: `upload_minutes(id, batch, *, history=…)`.
- **[ruff `F403`]** Без `import *`. Импорты — абсолютные (`from kardiomonitor.features…`),
  относительные — только внутри слайса (`from .schemas import …`).
- **[ruff `B006`]** Без изменяемых значений по умолчанию (`def f(x: list = [])`).
- **[ruff `S101`]** `assert` — только в тестах: с `python -O` он исчезает. Проверки — `if … raise`.
- **[ruff `DTZ`]** Без `datetime.now()` / `utcnow()` без часового пояса: только
  `datetime.now(UTC)`. Время без пояса в этом проекте — всегда ошибка.
- Магические числа → именованные константы с единицами: `MAX_BATCH_MINUTES = 7 * 24 * 60`.
- Современный синтаксис **[ruff `UP`]**: `X | None`, `list[int]`, `type Alias = …`, `match`.

## 6. Неизменяемость и видимость

- Доменные объекты — `frozen=True`; изменение агрегата — метод, возвращающий новое
  состояние или меняющий его под контролем инварианта.
- Схемы Pydantic — `frozen=True` (через общий `ApiModel`).
- Видимость — минимальная: из слайса наружу виден только `router` (**[import-linter]**);
  внутри модуля помощники — с `_`.
- Модуль при импорте ничего не делает: не подключается к базе, не читает файлы и
  переменные окружения, не создаёт `FastAPI()` кроме фабрики `create_app`.

## 7. Ошибки

- **Нарушение правила предметной области** (пульс 300, пакет больше 7 суток) —
  `DomainRuleViolation` (или подкласс) из `shared_kernel`, сообщение на русском.
  `app/errors.py` превращает его в `422` с `application/problem+json`.
- **Ожидаемые исходы сценария** (пациент не найден, телефон отозван) — возвращаемые
  типы, а не исключения. Эндпоинт явно переводит их в HTTP (`404`, `409`), см.
  [api-contract.md](api-contract.md).
- **`ProblemError` (`platform.web`) — только в `router.py`, `api.py` и зависимостях**,
  никогда в домене и сценарии: они не знают об HTTP. `HTTPException` не используется —
  у него нет стабильного `code` для клиента.
- **Исключения инфраструктуры** (`sqlalchemy.exc.*`, `httpx.*`) переводятся в доменные на
  границе — в `data/`, если у них есть смысл для предметной области. Иначе — пусть
  поднимаются: `app/errors.py` ответит `500` и запишет трассировку.
- **[ruff `E722`, `BLE001`, `S110`]** Без голого `except:`, без `except Exception: pass`.
  Перехватывайте конкретный тип. Широкий `except Exception` — только на границе
  (обработчик ошибок), с логом и `raise`.
- Перевыброс — с причиной: `raise PatientNotFoundError(...) from error` (**[ruff `B904`]**).
- Не перехватывайте `BaseException` и `asyncio.CancelledError` — это ломает отмену и
  остановку сервера.
- Ошибки программиста (нарушен контракт функции) — `raise ValueError/TypeError(...)`
  с сообщением, объясняющим причину; они дают `500`, и это правильно.

## 8. async и конкурентность

- Эндпоинты и зависимости с вводом-выводом — `async def` с асинхронными библиотеками
  (`asyncpg` через SQLAlchemy, `httpx.AsyncClient`).
- **[ruff `ASYNC`]** В `async def` нет блокирующих вызовов: `time.sleep`, `requests`,
  синхронный драйвер БД, `open()` больших файлов, `subprocess.run`. Блокирующую или
  CPU-тяжёлую работу — в `await asyncio.to_thread(...)` или в эндпоинт `def` (FastAPI
  выполнит его в пуле потоков).
- Таймауты на всё внешнее: `async with asyncio.timeout(seconds):`; у `httpx` — явный
  `timeout=`; у пула БД — `pool_timeout`, у запросов — `statement_timeout`.
- Параллельные задачи — `asyncio.TaskGroup`. **[ruff `RUF006`]** Без «запустил и забыл»
  `asyncio.create_task(...)` без сохранённой ссылки.
- `BackgroundTasks` — только для некритичного (лог, метрика): задача теряется при
  перезапуске. Важная фоновая работа — отдельный воркер, через ADR.
- `AsyncSession` не делится между задачами: одна сессия — один запрос — одна корутина.

## 9. FastAPI и dishka

- **Фабрика приложения:** `create_app(settings=None, *overrides) -> FastAPI`. Тесты создают
  своё приложение со своими настройками и провайдерами-подменами.
- **`lifespan`, а не `@app.on_event`:** при запуске — схема базы (демо), при остановке —
  `container.close()` (закрывает engine и другие ресурсы `Scope.APP`).
- **Зависимости — dishka** ([ADR-0003](adr/0003-dependency-injection-dishka.md)): роутер слайса
  `APIRouter(route_class=DishkaRoute)`, параметры `FromDishka[Порт]`. Реализации связываются в
  `provider.py` контекста. Новый порт → `Protocol` в `domain/`, реализация в `data/`,
  строка `provide(...)` в провайдере.
- **FastAPI `Depends` — только HTTP-детали:** схема безопасности для OpenAPI (`bearer_scheme`),
  заголовок `X-Dashboard-Key` (`require_dashboard_access` с `@inject`).
- **Проверки — в провайдере или зависимости:** «токен действителен» — провайдер
  `CurrentPatient` (иначе `NotAuthenticatedError` → 401), «пациент существует» —
  `require_patient` (иначе 404). Эндпоинт не повторяет проверку.
- **Модель ответа — через аннотацию возврата:** `-> UploadReceiptOut`. Не возвращайте
  ORM-объекты, доменные объекты и `dict`.
- **Отдельные схемы запроса и ответа** (`…In`, `…Out`), даже если поля совпадают сегодня.
- **Явный `status_code`** для всего, кроме `200`: `201` при создании, `204` без тела.
- **Ожидаемые ошибки — `ProblemError(status=…, code=…, title=…)`** из `platform.web`;
  `HTTPException` не используется — у него нет `code`.
- **Документирование:** `summary=` на русском, docstring эндпоинта — описание для OpenAPI.
- `APIRouter(prefix="/api/v1", tags=[...])` — в каждом слайсе; версия — часть пути.
- Без `Request` в эндпоинтах: значение — параметром, `FromDishka` или провайдером.
- Middleware — только сквозная техника (request id); проверки доступа — в сигнатуре эндпоинта.

## 10. Pydantic v2

- Только API v2: `model_validate`, `model_dump`, `ConfigDict`, `field_validator`,
  `model_validator`. Без `class Config`, `.dict()`, `.parse_obj()`, `@validator`.
- Общая база схем — `platform.web.ApiModel` с
  `ConfigDict(extra="forbid", frozen=True, str_strip_whitespace=True)`.
  `extra="forbid"` — опечатка в поле от клиента даёт `422`, а не тихую потерю данных.
- Время: в запросах — `AwareDatetime` (без пояса — `422`), в ответах — `UtcDatetime`
  из `platform.web` (всегда UTC с `Z`, как обещает контракт).
- Ограничения формата — в типах: `Annotated[int, Field(ge=0, le=255)]`, `UUID`, `Literal[...]`.
- Схема знает, как перевести себя в домен и обратно: `def to_domain(self) -> MinuteBatch`,
  `@classmethod from_domain(cls, receipt) -> Self`. Домен о схемах не знает.
- Схема проверяет **формат**, домен — **правила**. Правило с собственным `code` (размер
  пакета, повтор минуты) не дублируйте в `Field`: иначе клиент получит общий
  `invalid_request` вместо точного кода. Диапазон пульса в `Field` допустим — ради OpenAPI.
- Настройки — `pydantic-settings`: `Settings(BaseSettings)` с `env_prefix="KARDIO_"`,
  секреты — `SecretStr`; пустое значение в `.env` — «не задано». `.env` не коммитится;
  пример — `.env.example`.

## 11. SQLAlchemy 2.0 и база данных

- Только стиль 2.0: `select()`, `insert()`, `Mapped[...]`, `mapped_column()`; без
  `session.query()`.
- Таблицы — в `features/<контекст>/data/tables.py`, классы `…Row`, имена таблиц —
  `snake_case` во множественном числе (`activity_minutes`). Общая `Base` с naming convention
  — в `platform/db`.
- Время — тип `UtcDateTime` из `platform/db` (SQLite не хранит пояс: пишем UTC, читаем
  с UTC; время без пояса записать нельзя). Имена: `*_at` — момент, `*_on` — дата.
- В async **нет ленивой загрузки**: связи — `lazy="raise"`, нужные данные —
  `selectinload` или отдельный запрос. Иначе — `MissingGreenlet` в рантайме.
- Массовая запись — `sqlite.insert(...).on_conflict_do_update(...)` порциями по 1000 строк
  (лимит параметров SQLite), не циклом `session.add`. Это и делает загрузку идемпотентной.
- `expire_on_commit=False` у sessionmaker — объекты читаемы после фиксации.
- **Транзакцию фиксирует сценарий** (`await transaction.commit()` до возврата), не
  репозиторий и не финализатор: dishka закрывает сессию уже после ответа
  ([ADR-0005](adr/0005-transaction-per-request.md)).
- Схема демо — `create_all` при запуске, без миграций ([ADR-0007](adr/0007-sqlite-for-demo.md)).
  Перед реальными пациентами — Alembic: автогенерация → **прочитать и поправить руками** →
  `upgrade` → `downgrade` → `upgrade`; применённую миграцию не редактировать.
- Удаление колонок и таблиц с данными пациентов — только с согласия человека.
- Индексы — под реальные запросы: первичный ключ `(patient_id, started_at)` для истории.
- Сырой SQL — только через `text()` с параметрами; без f-строк в SQL (**[ruff `S608`]**).

## 12. Комментарии и документация

- Комментарий объясняет **почему**, а не что.
- Docstring (на русском) обязателен для: эндпоинтов (уходит в OpenAPI), доменных типов,
  портов, сценариев. Формат — короткая первая строка, затем подробности при необходимости.
- Правило, которое нельзя вывести из кода (почему 10 080 минут, почему перезапись) —
  со ссылкой на источник (раздел domain-model.md, ADR, android/docs).
- Не оставлять закомментированный код (**[ruff `ERA`]**) и `TODO` без пояснения что и почему.

## 13. Логирование и персональные данные

- `logger = logging.getLogger(__name__)`; **[ruff `T20`]** без `print` (кроме `scripts/`).
- Сообщения — с параметрами `logger.info("принято %d минут", count)`, не f-строками
  (**[ruff `G004`]**): форматирование только если уровень включён.
- **Никогда не логировать:** токены, заголовки `Authorization` и `X-Dashboard-Key`, тела
  запросов с данными пациента, имена пациентов, ключи браслета.
- В логе пациент — только `PatientId`; значения пульса и шагов — только в отладке на
  машине разработчика.
- Каждый запрос получает `request_id` (middleware), он пишется в лог и в ответ
  (`X-Request-ID`) — по нему ищут ошибку, а не по данным пациента.
- Токены хранятся только отпечатком (SHA-256); ключ панели сравнивается `secrets.compare_digest`.
- Ответ `500` не раскрывает трассировку и SQL — только `request_id`.
- CORS выключен: панель раздаётся с того же адреса, что и API. Включать — со списком доменов.
- Ссылка ngrok публичная: для демо с реальными данными задавайте `KARDIO_DASHBOARD_KEY`.
