# KardioMonitor — proof of concept

Проверяем, что с Xiaomi Mi Smart Band 6 (XMSH15HM) можно получить пульс и шаги
по Bluetooth LE без официального приложения. Скрипт запускается на ноутбуке с Linux
(BlueZ). Протокол затем переносится в мобильное приложение.

Требования клиники к системе (телефон, сервер, панель) — [docs/requirements.md](docs/requirements.md).

Экспериментальная проверка Xiaomi Smart Band 9 — [отдельный чек-лист](docs/band9-validation-checklist.md).
[Контекст и план полной поддержки Band 9](docs/band9-implementation-context.md) — результаты, протокол, точки интеграции и критерии готовности.
Диагностический прототип не используется как production-драйвер. В обоих Android-приложениях
начата отдельная read-only интеграция с явным протоколом и новым QR v3: auth, заряд,
GET настроек. **Полная поддержка Band 9 не готова**: история, суточные шаги, безопасный live stop,
SET и клинический/фоновый E2E остаются заблокированы до подтверждения.
Инструкции Python/BLE ниже относятся только к Band 6; на личном Band 9 не делать
reset/unpair и не выводить ключи или историю ради проверки.

## Что умеет `miband6_poc.py`

| Данные | Откуда | Нужен ключ |
| --- | --- | --- |
| Серийный номер, версии железа и прошивки | Device Information (0x180A) | нет |
| Батарея, % | Huami `0x0006` | да |
| Шаги, дистанция, калории за сегодня (+ обновления в реальном времени) | Huami `0x0007` | да |
| Пульс в реальном времени | Heart Rate (0x2A37 / 0x2A39) | да |

## 1. Получить ключ авторизации (auth key)

Браслет отдаёт данные только после авторизации AES-ключом, который выдаётся
серверами Xiaomi/Huami при сопряжении в официальном приложении. Создать ключ
самостоятельно нельзя.

Способ зависит от приложения, в котором сопряжён браслет.

**Mi Fitness (Xiaomi Wear).** Ключ есть в логах приложения, root не нужен.
Включите на телефоне отладку по USB, подключите его к компьютеру и выполните:

```bash
adb shell 'grep -ohE "(encryptKey|token|authKey|huamiAuthKey)[\":= ]+[[:xdigit:]]{32}" \
  /sdcard/Android/data/com.xiaomi.wearable/files/log/*.log \
  /sdcard/Android/data/com.mi.health/files/log/*.log 2>/dev/null' | tail -5
```

Если логов нет, **не отвязывайте и не сбрасывайте** рабочий браслет ради получения
ключа: это меняет доступ и может затронуть данные. Несколько найденных ключей неоднозначны;
нельзя выбирать просто последний. Для Band 9 используйте только привязанный к нужной
модели локальный workflow из [чек-листа](docs/band9-validation-checklist.md), без вывода
ключа в терминал. Применимость облачного получения ключа к Band 9 отдельно не подтверждена.

Другой вариант — `huami-token --method xiaomi --bt_keys` (запрашивает серверы
Mi Fitness). Не работает, если Xiaomi требует подтвердить вход (2FA).

**Zepp Life (бывший Mi Fit).** Запустите `python tools/zepplife_key.py`: вход
выполняется в браузере, и скрипт выводит ключ с серверов Huami. Ещё есть
приложение huafetcher и вариант с root-доступом:
`sqlite3 /data/data/com.xiaomi.hm.health/databases/origin_db_<ID> "select AUTHKEY from DEVICE"`.

Важно: **не отвязывайте** браслет в приложении и не сбрасывайте его. Иначе ключ
станет недействительным, и его придётся получать заново.

Подробнее: <https://gadgetbridge.org/basics/pairing/huami-xiaomi-server/>

## 2. Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Перед подключением **выключите Bluetooth на телефоне** (или закройте Zepp Life).
Браслет держит только одно соединение и, пока подключён к телефону, не виден.

```bash
# найти браслет и его MAC-адрес
python miband6_poc.py --scan

# без ключа: проверить подключение и прочитать версию прошивки
python miband6_poc.py --mac AA:BB:CC:DD:EE:FF --dump

# с ключом: батарея, шаги и пульс в течение 5 минут, запись в CSV
export MIBAND_AUTH_KEY=0123456789abcdef0123456789abcdef
python miband6_poc.py --mac AA:BB:CC:DD:EE:FF --duration 300 --csv data.csv
```

Пример CSV:

```
timestamp,metric,value
2026-10-09T14:00:01,firmware,1.0.6.10
2026-10-09T14:00:02,battery_percent,78
2026-10-09T14:00:02,steps,4213
2026-10-09T14:00:09,heart_rate_bpm,74
```

## 3. История за прошедшее время (`fetch_history.py`)

Браслет сам записывает данные за каждую минуту: пульс, шаги, тип активности
и сон. Скрипт выгружает их за выбранный период, сохраняет в CSV и печатает
сводку по часам.

```bash
python fetch_history.py --mac AA:BB:CC:DD:EE:FF --since 24h --csv history.csv
python fetch_history.py --mac AA:BB:CC:DD:EE:FF --since 2026-10-08T00:00
```

- Данные остаются на браслете (подтверждение о получении не отправляется),
  поэтому Mi Fitness их тоже получит.
- Пульс в истории есть только с той частотой, которая задана в Mi Fitness
  (Пульс → частота измерения). Для наблюдения за реабилитацией поставьте **1 минуту**.
- Тип активности (`kind`): 115 — браслет снят, 118 — заряжается, 120 — сон.

## 4. Android-приложение (`android/`)

Прототип на Kotlin и Jetpack Compose (minSdk 26). Умеет:
- подключаться к браслету по QR-коду или по введённым вручную MAC-адресу и ключу;
- проходить авторизацию Huami 2021 (старая авторизация тоже поддерживается);
- показывать батарею, шаги за сегодня и пульс в реальном времени;
- выгружать поминутную историю в SQLite, начиная с прошлой синхронизации
  (при первом запуске — за 7 дней);
- синхронизироваться в фоне каждые 30 минут (WorkManager): подключиться, забрать новые
  данные и отключиться. Работает при закрытом приложении и заблокированном экране,
  но Android может откладывать запуск в режиме энергосбережения. При каждом
  подключении в базу пишется заряд браслета (таблица `battery`);
- задавать частоту фонового измерения пульса (1, 5, 10, 30 мин или выкл.).
  Настройка повторно записывается в браслет при каждом подключении;
- показывать статистику по дням: шаги, средний, минимальный и максимальный
  пульс, график пульса за сутки и шаги по часам.

Приложение также отправляет данные на сервер клиники (`backend/`, панель — `frontend/`):
см. [backend/README.md](backend/README.md).

```bash
cd android
./gradlew testDebugUnitTest      # тесты протокола: сверка с эталонными значениями из Python
./gradlew installDebug           # установка на телефон, подключённый по adb
```

QR-код для пациента:

```bash
python tools/make_qr.py --mac E7:19:F3:6C:04:9E           # ключ берётся из MIBAND_AUTH_KEY
python tools/make_qr.py --mac E7:19:F3:6C:04:9E --out band.svg
```

Перед подключением закройте Mi Fitness или отключите ей разрешение
«Устройства поблизости»: браслет держит только одно соединение.

## Диагностика

- **Браслет не найден.** Выключите Bluetooth на телефоне и проверьте, что браслет рядом.
- **`Not Connected` сразу после чтения серийного номера, а в `journalctl -u bluetooth`
  есть `No agent available`.** BlueZ пытается сопрячься с браслетом из-за его
  HID-сервиса. Добавьте `LEAutoSecurity=false` в секцию `[General]` файла
  `/etc/bluetooth/input.conf` и выполните `sudo systemctl restart bluetooth`.
- **«Неверный ключ авторизации».** Браслет перепривязывали после получения ключа.
  Получите ключ заново.
- **Ответ `108307` и надпись на браслете «Сначала обновите приложение».** Прошивка
  1.0.6.10+ требует авторизацию по протоколу Huami 2021 (`huami2021.py`). Скрипт
  выбирает её сам, если у браслета есть характеристики `0x0016`/`0x0017`. Флаг
  `--legacy-auth` включает старую авторизацию.
- **«Отклонил запрос (auth/crypt flags)».** Прошивка требует другой вариант
  авторизации. Пришлите версию прошивки (её печатает скрипт).
- **Пульс приходит как 0.** Идёт первое измерение (5–15 с) или браслет снят.
  Наденьте браслет плотнее.

## Ограничения PoC

- Из истории выгружаются только поминутные данные активности. Отдельные
  наборы (SpO2, стресс, PAI, тренировки) пока не выгружаются.
- Браслет — бытовое устройство, а не медицинское изделие. Его данные подходят
  для наблюдения за динамикой, но не для диагностики.

# Выдача браслетов через персонал клиники. Пациент не видит ни Mi Fitness, ни аккаунт Xiaomi

```
Сотрудник (один раз на браслет)            Пациент
───────────────────────────────            ─────────────────────────
1. Привязать браслет в Mi Fitness          4. Установить наше приложение
   под аккаунтом клиники                   5. Отсканировать QR-код
2. Достать ключ (логи или вход в аккаунт)     → приложение подключается
3. Выдать QR-код: MAC + ключ                  к браслету напрямую
   (Mi Fitness на телефоне пациента не нужна)
```

Чем это хорошо:

- Сложность и зависимость от неофициального API остаются во внутреннем инструменте клиники, а не в приложении пациента. Если этот инструмент сломается, данные пациентов продолжат поступать.
- Пароли от аккаунтов Xiaomi не хранятся в приложении пациента.
- Mi Fitness не забирает данные с браслета (именно это мы видели в последней выгрузке), а прошивка не обновится сама и не сломает протокол.
- Шаги 2–3 автоматизирует утилита персонала — отдельное Android-приложение (пока спецификация:
  [android/docs/staff-app/](android/docs/staff-app/README.md)). До неё — `tools/zepplife_key.py`,
  `huami-token` и `tools/make_qr.py`.

Что стоит учесть

Для мониторинга после инфаркта зависимость от обратной разработки протокола Xiaomi — серьёзный риск. Обновление прошивки может в любой день остановить сбор данных. Кроме того, пульс относится к данным о здоровье, а это отдельная категория персональных данных по 152-ФЗ. Если проект дойдёт до пилота с пациентами, стоит сравнить Mi Band с устройствами, у которых есть официальный SDK:

- Polar H10, Polar Verity Sense — бесплатный официальный SDK. Нагрудный датчик H10 даёт точные RR-интервалы, его часто используют в исследованиях кардиореабилитации.
- Withings ScanWatch — сертифицированная функция ЭКГ, есть официальный API.
- Garmin — Health SDK, лицензия по запросу.

Для прототипа Mi Band 6 подходит: дешёвый и уже работает. Но архитектуру приложения стоит строить так, чтобы источник данных можно было заменить.
